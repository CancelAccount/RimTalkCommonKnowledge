## 4. 非功能需求

| 项 | 要求 |
| --- | --- |
| 性能 | 注入的**重活**（遍历据点算距离、拼串、查库）只在新档一次 + 每读档一次 + 定时校正时执行；规模为 O(派系数 × 据点数 + 派系数 × 异种人数)，派系数通常 < 20、据点总数 < 200、异种人数 < 20，单次开销可忽略。定时校正按 `REFRESH_INTERVAL_TICKS`（2500 tick）节流（FR-11），**不得**在 `GameComponentUpdate`（每帧）或节流判定之前做任何扫描 |
| 刷新开销 | 校正的常态是「查库 + 拼串比对」，未产生写入时零写入、零日志（FR-11） |
| 存档兼容 | 只新增常识条目，不改原版与上游任何存档字段；注入条目随存档自然保存（证据 ⑤）。旧档可直接装/卸 |
| 依赖隔离 | 仅 `RimTalkMemoryBridge` 一个文件 `using RimTalk.Memory`，其余代码不感知上游类型（D9） |
| 补丁隔离 | Harmony 补丁只集中在 `Patches\FactionCompositionUiPatch.cs`，且只在 `FactionInfoMod` 构造期 `PatchAll` 一次；补丁体只做「读 Def + 拼串」，不写状态、不落盘，异常就地 catch 降级（FR-14） |
| 缺失依赖 | 若上游常识库取不到（`Current.Game == null`、上游未启用），记一次中文告警并静默退出，不抛异常、不刷屏 |
| DLC 降级 | 无 Biotech 时异种人一遍整体跳过且不报错（FR-9.0）；无 Ideology 时意识形态段跳过（FR-3 ②）。两项降级互不耦合 |
| 版本兼容 | 只声明 1.6；`supportedVersions` 单条 |

## 5. 风险与护栏

| # | 风险 | 护栏 |
| --- | --- | --- |
| RK-1 | 派系名是常见字 → 对白频繁误触发 | 标签策略固有代价（D3）。缓解：日志暴露注入清单便于排查；必要时后续提供「标签排除名单」设置。（我方派系条目虽已纳入（D33），但其触发词同样只是派系名本身，不额外放通用词） |
| RK-2 | 上游 API 签名变更（版本升级） | 编译期即报错（D9）；`RimTalkMemoryPatch.dll` 版本升级后必须复跑 [02 证据表](../02-接口取证证据表.md) |
| RK-3 | `PlayerGoodwill` 在无关系时打 Error 日志 | 必须先用 `faction.HasGoodwill` 门控（FR-3 ③） |
| RK-4 | 内容含换行破坏导入导出格式 | 内容强制单行（FR-3 / FR-9.2），代码里不得出现 `\n` |
| RK-5 | 读档补齐把玩家手动删除的条目加回 | 已知行为（D8 / D22），先不处理，观察反馈 |
| RK-6 | 在上游未启用/未加载时崩溃 | 桥接类内全部 try/catch + 前置空库判定（FR-8） |
| RK-7 | 据点距离在多层星球（Odyssey）下取到 `int.MaxValue` | 距离值无效（`<= 0` 或 `>= int.MaxValue`）时省略距离子句（FR-3 ④） |
| RK-8 | 高权重（我方 `0.95` / 其它 `0.80`，D43）可能把同分的其它常识挡在注入名额之外 | 影响面受限：仅当对白**真的出现该派系名**时该条目才参与竞争（FR-4），不是常态占位；且两个权重都是可调设置，实测若过强可下调。分档本身即为缓解——`0.80` 与社区「派系本体」齐平，不再压过社区条目；`0.96\~1.0` 整段留给系统级（设置界面两个滑条即为此预留） |
| RK-9 | **派系异种人构成失准**：某 mod 只通过 `PawnKindDef.xenotypeSet`（而非 `FactionDef.xenotypeSet`）指定成员异种人，若只读派系级会写成「全员基础异种人」并漏扫其特色异种人 | 已按游戏口径纳入兵种级来源（D40、证据 ㊶）：FR-9.1 三处来源累加，特色异种人能扫出、能进反向索引与标签；同时**派系级分布不可信**的派系（`xenotypeSet == null` 而兵种级另有设置等）**省略第 ⑤ 段**并记日志，不武断写「智人种 100%」。若某 mod 连兵种级也不声明，走预设适配（FR-6） |
| RK-10 | 无 Biotech DLC 时 NRE（`XenotypeDefOf.Baseliner` 等为 null） | FR-9.0 强制先判 `ModsConfig.BiotechActive`；所有 `xenotypeSet` 访问前判 `null`；`XenotypeSet` 遍历只用 `Count` + 索引器（证据 ㉕） |
| RK-11 | 异种人 tag 与派系名/其他异种人名撞车 | 两条都保留、不覆盖，记日志告警（D23） |
| RK-12 | 异种人常识条目数量膨胀（mod 加大量异种人） | 集合只取「本局有效派系相关」（D12）而非全量 Def；`includeXenotypes` 可整体关闭；极端情况下按 `xenotypeGeneCount = 0` 压短内容 |
| RK-13 | 派系名自身含 `,` `，` `、` `;` `；` 时，被上游 `GetTags()` 切成碎片（D17 引入了并列分隔符，风险面变大） | 幂等判定按 **tag 第一段** 匹配而非整串（证据 ㉗），故碎片化只影响「触发词是否含杂讯」，不会导致重复注入或误删；如实测出现问题，可把并列词改放 `content` 而非 `tag` |
| RK-14 | 特征异种人判定武断：`chance` 并列最大或数据缺失时若硬写结论，会给出错误的世界观常识 | 判定口径收紧为「非基础异种人 chance **严格最大且唯一**，且 `> BaselinerChance`」，否则返回 `null`（既不并入标签、也不写内容段）；派系级 `xenotypeSet == null` 时退用兵种级集合，**仅当非基础异种人唯一**才认定为主流，否则返回 `null`（D40、RK-9 护栏） |
| RK-15 | 本 mod 设了「可提取 / 可匹配」，但玩家侧没开上游的「常识链式匹配」（默认关、且 `canBeMatched` 只作用于第 2 轮起），可能被误认为功能失效 | FR-10 已写明生效前提；关卡式匹配时**不影响第 1 轮直接匹配**（该轮不受 `canBeMatched` 限制），故核心功能不依赖此设置；在 README/工坊说明中提示玩家「如需常识互相串联，请在上游设置里开启常识链式匹配」 |
| RK-16 | 定时轮询的常态开销（长局累积） | 节流到 2500 tick，且挂在 `GameComponentTick`（每 tick）而非 `GameComponentUpdate`（每帧）；常态只做「查库 + 拼串比对」，不写库、不打日志。若实测有性能问题，可调大 `REFRESH_INTERVAL_TICKS`（S4 起可做成设置项） |
| RK-17 | 玩家手动编辑过本 mod 的条目，会在下次校正时被覆盖 | 判定范围限定为「tag 第一段 = 派系名 **且** 内容以 `【派系】` 开头」，与 FR-5.1/5.4 同口径；保留该前缀即视为本 mod 管理范围。若玩家想固化自己的版本，应改用**不带** `【派系】` 前缀的自建条目 |
| RK-18 | 非质变数据的滞后：好感度累积、领袖更替、据点增减最多滞后 3 天才写入 | 这是 FR-12 的刻意取舍——该类数据本就小步慢变，滞后对叙事无实质影响，而频繁改库的副作用（条目 id 变化、列表闪动、日志刷屏）更明显。**质变（关系翻转）不受冷却限制**。调试期可用开发者菜单「快速刷新」把冷却降到 1 小时 |
| RK-19 | 我方派系「建立时长」口径不精确：`Faction` 无创建时刻字段，只能退化为「游戏已进行时长」（`TicksGame`），严格说不是「派系建立」的时长 | 这是无据可查时的诚实近似（FR-13），已在需求里写明局限；未来若存档/DLC 提供更精确来源再收紧。**不引入新的持久化状态**去自造一个「建立时刻」 |
| RK-20 | 我方派系「飞船停留时长」可能读不到：只有 `map.wasSpawnedViaGravShipLanding` 的地图能反推着陆时刻，飞船停靠在已有地图上时没有任何字段记录 | FR-13 ③ 明确「读不到就降级为不含时长的句子」，**不编造数字**；同样不自造持久化状态记录着陆时刻 |
| RK-21 | 派系名 / 异种人名含上游 5 种分隔符时，标签会被切成碎片、主键比对失效，条目反复堆积 | FR-13 引入 `SanitizeTagPart`：拼标签与主键前把名字里的分隔符一律替换为空格（内容仍用原名）；首项与 `TAG_SEPARATOR` 保持一致（证据 ㉗） |
| RK-22 | 纳入玩家派系后，若沿用「对每个派系都取 `faction.PlayerGoodwill`」的写法，会在**创建新档时崩**：对玩家派系自身取好感度 → `RelationWith(自己)` 先打引擎 `Log.Error`，随后 `GoodwillSituationManager.GetMaxGoodwill` **NRE** | **取值前必须判 `faction.IsPlayer`**（`Faction.HasGoodwill` 只挡 `Hidden` / `temporary`，挡不住自己，证据 ㉞）。实现上好感度在该取值表达式里直接短路为 0；`PlayerRelationKind` 同理只对非玩家派系读。本条为**实测崩溃**后补录 |
| RK-23 | 读 `WealthTotal` 可能抛 `IndexOutOfRangeException`：它不是纯读取，会按需触发全图财富重算，而重算按 `cachedTerrainMarketValue[terrainDef.index]` 取地形价值；`Def.index` 默认值是 `ushort.MaxValue`，故任何「未被 `DefDatabase` 登记」的地形一旦进网格就会越界 | 该异常**与原版告警链路（`Alert_NeedJoySources`）同源、不是本 mod 引起的**（证据 ㉟），但本 mod 也会走这条读路径，故 `GetPlayerHomeWealth` **就地 try/catch**，失败即省略 ⑤ 财富段并只 `WarnOnce` 一次——不让外部数据异常连累整条我方派系条目（否则整条会落入「处理派系失败」而丢失）。此为**实测报错**后补录 |
| RK-24 | 我方派系内容（财富、建立时长）每小时都在变，若定时轮询也逐条打印「跳过（非质变改动，覆写冷却中）」，会每小时刷一次屏（开发者模式下还带栈） | 该行改为**仅首次同步（新档 / 读档）输出**：轮询期静默，只累加到汇总计数。与 FR-12「轮询常态就是什么都没变，只在真的重写时才说话」的既有口径一致 |
| RK-25 | 人口口径是**近似**而非与 UI 对齐：① `QuestUtility.IsQuestLodger()` 的语义是「该单位因任务带有额外所属派系」，比口语的「难民」宽；② 「临时成员」把任务寄居者与由我方招待的来客合并为一类；③ 遍历范围是「我方地图 + 商队 / 运输船 / 当前逆重飞船」，不含世界地图上与本局无关的人 | 这是**刻意取引擎自身语义**（`PawnsFinder` 筛选器 + `Pawn` 自身属性，证据 ㊱），不自造名单；口径稳定、可解释，宁可粗但一致。文案只作叙事用，**不承诺**与殖民者栏数字逐一对齐 |
| RK-26 | 我方派系的条目识别**依赖内容里的固定句**（`是我们自己所属的派系。`）：若为改文案而改动该句，存量存档里已写入的旧条目将**失去识别依据**，改名后旧条目会残留成重复项 | 该固定句在 `FactionKnowledgeConfig` 里带有「不可为改文案而改动」的显式警告注释，并被 `RimTalkMemoryBridge.FindManagedIdsByContent` 用作唯一识别口径；确需改文案时，必须先想好旧条目的迁移方案（证据 ㊲） |
| RK-27 | 机械族段「按型号 + 不立刻更新」的口径代价：① 型号构成与气候**不进质变指纹**，机械族增减 / 换型号最多滞后 3 天才写入；② 型号名是**本地化文本**（`kindDef.LabelCap`），切换语言后同一台机械的型号名会变，内容随之重写 | ① 滞后是用户明确要求（机械族持续充放电、机械师更替频繁，进指纹会高频立即重写，D37）；② 型号名**按名排序**保证同集合下内容稳定可复现；语言切换本就应触发内容重写（全部文案均为本地化文本），非异常。两段都在读不到数据时整段跳过（无 Biotech / 无主基地），不写占位噪声 |
| RK-28 | 隐藏派系纳入注入的两点固有代价：① **主键用类型标签**——隐藏派系无自定义名，`Name` 回退 `def.LabelCap`，若与某普通派系名同字（或两个隐藏派系标签相同），二者 tag / 主键撞车，触发时两条内容都会注入；② **标签是本地化文本**，切语言后 `def.LabelCap` 变，条目随之重写 | ① 与 D21（同名派系）同源、同一处理口径，先记日志告警不阻塞（本期不改）；② 切语言本就应重写全部文案，非异常。**关键是不得为此去自造「隐藏派系专用名」**——那才是真正的「注入隐藏派系没有的数据」（D39 第一约束） |
| RK-29 | 成员种族口径的两点取舍：① 含非人类人形种族时异种人构成段**整体让位**——若该派系同时存在有效的异种人分布（HAR 种族 + 专属 `XenotypeDef` 的 mod），这部分信息不在派系条目里，只能从对应的**异种人条目**读（FR-9.1 的集合仍会收录，不丢）；② 种族名是**本地化文本**（`race.LabelCap`），切换语言后同一派系的条目会重写 | ① 让位是刻意的：HAR 种族在 Biotech 异种人体系里一律登记为智人种，写「智人种 100%」是误导；让位不等于丢信息（异种人条目仍在）。② 切语言本就应重写全部文案，非异常。判定只读 `pawnGroupMakers`、不加持久化状态（D41、证据 ㊷） |
| RK-30 | 界面补丁的宿主是**属性 getter**（`FactionDef.Description` / `Faction.GetReportText`），会被 tooltip **每帧**触发；若构建过程抛异常，会连累整个派系页绘制并刷屏（`OnGUI` 异常） | 构建整体 try/catch，异常一律降级为「本次不追加」并只 `WarnOnce` 一次（FR-14）；补丁只读 Def、不写状态，单次开销与游戏自身拼串同级 |
| RK-31 | 界面追加文本可能与游戏自带「成员异种人概率」重复（游戏已在 `FactionDef.Description` 里附该段） | **只在游戏自身看不出的情形输出**（有非人类人形种族 / 派系级分布不可信），其余返回 `null` 不追加（FR-14）；对派系级分布正常的原版派系，界面文本与改动前逐字一致（§9.8 第 44 项） |
| RK-32 | 「定义原文让位」的查重（D43）需对每个派系 / 异种人做一次上游**全库子串扫描**（`FindKnowledge` 为 `O(全库)`，社区库 25653 条），同步开销随之上升 | 同步本身已被节流（新档 / 读档 / 每 1 游戏小时一次），扫描是纯内存 `IndexOf`、无 IO 无副作用；实测量级可忽略。若将来常识库规模再翻数倍，改为「一次性建首段标签集合 + `O(1)` 查询」即可（方法已收敛在 `RimTalkMemoryBridge`，改动面小） |

> **已拆出的风险**：社区包导入相关 **RK-33 / RK-34** 见 [04-社区包导入.md](../04-社区包导入.md) §5。本篇不再重复叙述。
