## 1. 背景与目标

RimTalk-Expand Memory 提供了一套「常识库」：条目形如 `[标签|重要性]内容`，殖民者对白文本中出现标签子串时自动匹配注入（证据 ③）。但相关的世界设定需要玩家手工录入。

本 mod 在新开档时自动把世界地图上每个派系的客观设定、以及与该派系相关的异种人设定整理成常识写入该库，让殖民者一开口就"认识"这个世界的势力格局与种族构成。

**目标**：零手工录入，新档开局即拥有全部派系与其相关异种人的常识；旧档装上本 mod 也能补齐。

**与上游的分工**：上游 `PawnStatusKnowledgeGenerator` 已经会为每个殖民者写「个人状态」条目，其中含其种族与异种人（形如 `{殖民者}的种族是{种族名}-{异种人名}`，例：「小明的种族是人类-智人种」，证据 ㉖）。本 mod 写的是**世界级设定**（这个异种人是什么、有何标志基因、哪些派系由他们组成），二者互补，不重复。

---

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 常识库 | RimTalk-Expand Memory 的 `CommonKnowledgeLibrary`，随存档保存（证据 ⑤） |
| 条目 / entry | `CommonKnowledgeEntry`：`tag`（触发标签）+ `content`（注入内容）+ `importance`（重要度 0\~1） |
| 派系常识 | 本 mod 注入的常识条目（内容前缀 `【派系】`），tag 为某派系名，或以半角逗号并列该派系的**唯一特征词**——优先成员种族名（D41），否则特征异种人名（D17） |
| 异种人常识 | 本 mod 注入的、`tag` 为某异种人名（`XenotypeDef.LabelCap`）的常识条目（内容前缀 `【异种人】`），需 Biotech DLC |
| 有效派系 | 通过 FR-2 筛选后、值得注入常识的派系 |
| 桥接类 | 本 mod 中唯一直接引用 `RimTalkMemoryPatch.dll` 的类（`RimTalkMemoryBridge`），隔离上游依赖 |

## 3. 功能需求

### FR-1 注入时机与生命周期

| 场景 | 钩子 | 行为 |
| --- | --- | --- |
| 新开档 | `GameComponent.StartedNewGame()` | 为全部有效派系注入常识（无论是否已存在同标签条目 → 先清理再写入，见 FR-5） |
| 读档 | `GameComponent.LoadedGame()` | 仅**补齐缺失项**：逐派系判定，已有则跳过，缺失则写入 |
| 切图 / 换档 / 读档重进 | 同 `LoadedGame()` | 同上（幂等） |

- 使用 `GameComponent` 子类，靠 `typeof(GameComponent).AllSubclassesNonAbstract()` 自动发现（证据 ⑪），**不需要 Def、不需要 Harmony**（D10）。
- 构造签名必须为 `public XxxComponent(Game game)`，且**不能**写 `: base(game)` —— `GameComponent` 自身没有 `(Game)` 构造，写了直接 **CS1729**；`Game` 参数只是为了匹配 `Activator.CreateInstance(type, this)`，基类走隐式无参构造（证据 ⑪，已编译验证）。
- 不在 `WorldComponent.FinalizeInit`、不在 `FactionGenerator` 补丁上做注入（D1 理由：玩家派系与玩家关系在那些时点尚不存在，证据 ⑩）。
- 全程不得在 `Current.Game == null` 或 `Find.World == null` 时调用常识库（证据 ②：`GetCommonKnowledge()` 在无 Game 时返回**游离的空库**，写进去会静默丢失）。
- **执行顺序**：同一次回调内先跑**派系**一遍（FR-2\~FR-5），再跑**异种人**一遍（FR-9）。异种人一遍依赖派系一遍的产物（FR-2 的有效派系集合 + 双向引用所需的派系名），故顺序不可颠倒。
- 两次旁路互相独立 try/catch：异种人一遍失败不得影响已完成的派系注入。

### FR-2 派系筛选

遍历 `Find.FactionManager.AllFactionsListForReading`（`List<Faction>`，内部列表引用，**只读遍历、不增删**，证据 ⑨㉓），按以下规则筛选：

| 筛选条件 | 成员 | 处理 |
| --- | --- | --- |
| 玩家派系 | `faction.IsPlayer` | **纳入**（[D33](01-08-决策表.md#6-决策表) 修订 D2 原口径）：内容走**独立**模板（FR-13），不套用普通派系的五段 |
| 隐藏派系 | `faction.Hidden` | **纳入**（[D39](01-08-决策表.md#6-决策表) 修订本条原口径）：机械族 / 虫族 / 古代人 / 实体等，以及 mod 自带的世界观隐藏派系（常是世界观的重要组成部分）。这类派系缺数据（无自定义名、无与玩家关系、无领袖、无意识形态），内容**逐段判缺跳过**，**不写引擎兜底值 / 不适用值**（见 FR-3） |
| 临时派系 | `faction.temporary` | **排除**（临时敌对/商队等，不构成世界格局） |
| 已覆灭派系 | `faction.defeated` | **不排除**：「已被我们打败的势力」本身是有价值的谈资；但若同时满足「据点数为 0」且「无领袖」，则视作空洞常识跳过，只在内容里保留一句「他们已被我们击败」 |

参考基线：同作者 `NewThreeKingdomsArt` 的 `MemeWeightApplier.InjectFactionNames` 仅排除 `IsPlayer` / `Hidden`（`Source/MemeWeightApplier.cs#L55-L62`）；本 mod **不再排除 `Hidden`**（D39：隐藏派系常是世界观的组成部分），相对基线只多一项 `temporary` 排除。

**同名派系**：条目主键取 `faction.Name`（派系名），两个派系同名时会共用同一主键；此时**不消歧、不合并**——两条各自成条写入，仅经 `KnowledgeLog.WarnOnce` 记一次告警（见 [§6 决策表](01-08-决策表.md#6-决策表) D21）。

### FR-5 幂等、补齐与清理

1. **已注入判定**：`CommonKnowledgeAPI.FindKnowledge(factionName)` 取回**候选**条目，再逐条要求两个条件同时成立 → 视为本 mod 注入的条目：① 条目 tag 的**第一段**与派系名全等（借上游 `GetTags()` 切分，D17 下 tag 可能是「派系名、异种人名」）；② `content.StartsWith("【派系】")`。

   **为什么必须补条件 ①**：`FindKnowledge` 是 **tag 子串**匹配（证据 ⑥），查「帝国」会连带命中 tag 为「新帝国」的条目；只用内容前缀判会把别人的条目当成自己的删掉。**为什么用第一段而非整串**：tag 尾段（异种人名）会随派系成员构成变化，只有首段（派系名）是稳定主键（证据 ㉗）。
2. **写入与校正共用一套判定**（FR-11 / D19）：库内**无**条目 → 写入；库内内容与新建内容**逐字一致** → 不写，仅校准好感度基准；差异**仅**来自好感度且差值未达阈值 → 本次不写；其余情况（关系质变、领袖更替、据点增减、成员变化、模板升级）→ `RemoveKnowledge(id)` 后重写。
3. **触发时机**：新档 `StartedNewGame()`、读档 `LoadedGame()`、运行中定时轮询（FR-11）三处共用上述逻辑，因此**不存在**「新档必须先删后写」的特殊路径；原 `replaceExisting` 参数随之取消。
4. **不触碰**玩家自己录入的条目：只有带 `【派系】` 前缀的条目才属于本 mod 管理范围。
5. **上游 API 返回 null 时**（`AddKnowledge` 内部异常已被上游 catch 并 `Log.Error`，返回 `null`，证据 ①）→ 记中文告警，继续处理下一个派系，不中断整体流程。

### FR-10 条目扩展开关（可提取 / 可匹配）

两类常识条目（派系、异种人）一律**显式**开启两个扩展开关（D18）：

| 开关 | 取值 | 含义（证据 ㉘） |
| --- | --- | --- |
| `canBeExtracted` | `true` | 条目内容可被**提取**，拼进下一轮的链式匹配文本，充当后续匹配的线索 |
| `canBeMatched` | `true` | 条目可被**链式匹配**（第 2 轮起）命中 |

- 实现方式：`CommonKnowledgeAPI.AddKnowledgeEx(tag, content, importance, KeywordMatchMode.Any, targetPawnId: -1, canBeExtracted: true, canBeMatched: true)`。
  **不可**用 `AddKnowledge`：它完全不写这两个开关，而 `ExtendedKnowledgeEntry` 侧表新建时默认值是 **false**，等于条目既不提供链式线索、也不能被链式命中（证据 ㉘）。
- `targetPawnId = -1` = 不限定殖民者，任何殖民者都可匹配（`FactionKnowledgeConfig.TARGET_PAWN_ALL`）。
- **生效前提**：上游「常识链式匹配」设置默认**关闭**（`enableKnowledgeChaining` 默认 `false`），关闭时除第 1 轮外不再匹配，本项无害但也无效；开启后轮数由 `maxChainingRounds`（默认 `2`，UI 滑块 1\~5）控制。此前提登记为 RK-15。
