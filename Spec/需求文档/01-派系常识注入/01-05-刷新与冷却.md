## 3. 功能需求

### FR-11 内容校正与定时刷新

派系常识里含**易变数据**（③ 关系与好感度、④ 领袖与据点数量/距离、⑤ 成员构成、② 主流意识形态）。若只在开档写入一次，长局游玩后条目会与事实脱节——尤其好感度会**永久停在开档快照**。故写入与校正**共用一套比对式逻辑**（D19），三处触发：

| 触发点 | 说明 |
| --- | --- |
| `StartedNewGame()` | 新档：库内必然无条目 → 全部写入 |
| `LoadedGame()` | 读档：逐条比对，缺失则补、陈旧则重写、一致则不动 |
| `GameComponentTick()` | 运行中：每 `REFRESH_INTERVAL_TICKS`（2500 tick = 1 游戏小时）轮询一次 |

**每个有效派系的判定顺序**：

1. 库内**无**本 mod 条目 → 写入（新条目**不受**冷却限制）。
2. 库内内容与新建内容**逐字一致** → 不写，仅校准各项基准。
3. **质变**：质变指纹相对上次写入发生变化 → **立即重写，不受冷却限制**（FR-12）。普通派系指纹 = `PlayerRelationKind`（敌对 / 中立 / 盟友）翻转；**隐藏 / 临时派系改用固定键 `NoRelation`**（它们 `HasGoodwill` 为假、无可谈关系，硬取会触发引擎 `Log.Error` 并返回兜底值，故不取关系而取固定键，见 D39）；我方派系指纹 = 派系名 + 据点集合 + 飞船集合 + 殖民者数 + 奴隶数（FR-13）。
4. 差异**仅**来自好感度数值，且 `|当前 − 上次写入| < GOODWILL_REFRESH_THRESHOLD`（10）→ 不写（此判定与冷却无关）。**我方派系不参与本步**（对玩家自身无好感度可言，见 FR-13）；**隐藏派系内容里本就没有好感度句**，同样不适用。
5. **非质变**改动（好感度累积、领袖更替、据点增减、成员变化、建立时长与财富增长、模板升级）→ 距上次写入未满 `REWRITE_COOLDOWN_TICKS`（3 天）则**本轮继续等待**，满了才重写（FR-12）。

**「仅好感度波动」怎么判**：把库内内容里的「上次写入的好感度句」（`FACTION_SEG_GOODWILL` 套上次值）**整句替换**为「当前好感度句」。该句模板固定、数值唯一，替换是安全的；替换后若与新建内容逐字相同，即证明其它各段都没变。任一前提不成立（无基准 / `HasGoodwill` 状态变化 / 其它段变化）都照常重写。

**为什么用内容逐字比对而非逐字段判断**：一次覆盖全部易变段，不必为每个字段维护脏标记；且本 mod 后续升级内容模板后，旧条目会在下次触发时自动升级。

**好感度基准的存放**：`Dictionary<int /* faction.loadID */, int /* 上次写入的好感度 */>`，仅存内存、**不持久化**（证据 ㉚）。读档后为空，会保守地重写一次，从而顺带校正存档期间产生的陈旧内容。

**范围与开销**：

- 异种人条目**不参与**定时刷新——其内容（描述、基因、出没派系）几乎不变，只做「缺失才补」。
- 轮询常态开销 = 每个派系一次「查库 + 拼串比对」（派系数通常 ≤ 20）；未产生写入时保持静默、不输出日志。
- 本节的比对式统一覆盖了 FR-5.2/5.3，故不再需要 `replaceExisting` 这类特殊路径。

### FR-12 非质变覆写冷却与调试开关

**为什么需要**：FR-11 的「检测」很便宜（只查库 + 拼串），但**写入**会让上游删条重建。好感度、据点、距离这类数据在长局里持续小步变化，若每次检出差异就写库，会在几小时内反复改库——对玩家浏览常识库的体验（条目 id 变化、列表闪动）与上游日志都不友好。

| 规则 | 值 | 说明 |
| --- | --- | --- |
| 校正**检测**间隔 | `REFRESH_INTERVAL_TICKS` = 1 游戏小时 | 只查库 + 拼串，不写库、不打日志 |
| **非质变**覆写冷却 | `REWRITE_COOLDOWN_TICKS` = 3 游戏天 | 距上次写入未满冷却则本轮跳过（记 Detail 日志） |
| **质变** | 无冷却 | 质变指纹相对上次写入发生变化 → 立即重写（普通派系 = 关系种类翻转；隐藏派系 = 固定键 `NoRelation`；我方派系见 FR-13） |
| 新条目 | 无冷却 | 库内无条目 → 直接写入 |
| 调试覆写冷却 | `DEBUG_REWRITE_COOLDOWN_TICKS` = 1 游戏小时 | 开发者菜单「快速刷新」开启时生效 |

**「质变」的判定**：与上次写入时记录的**质变指纹**做字符串比对。普通派系指纹 = `PlayerRelationKind`（敌对 / 中立 / 盟友）；**隐藏 / 临时派系取固定键 `NoRelation`**（无可谈关系，见 D39）；我方派系指纹 = 派系名 + 据点集合 + 飞船集合 + 殖民者数 + 奴隶数（FR-13）。基准存于 `Dictionary<int /* faction.loadID */, string>`，仅内存、**不持久化**；无基准（刚读档）时视为质变，以便立即校正陈旧内容。

**调试开关**：`KnowledgeDebug` 用 `[DebugAction]` 在开发者菜单注册按钮（`RimTalkCommonKnowledge` → 切换快速刷新（覆写冷却 3天 ↔ 1小时）），点击即在 3 天与 1 小时之间切换非质变覆写冷却，并在日志里回报当前生效值；开关只在内存、**不随存档保存**。用 `[DebugAction]` 而非 ModSettings 的原因：S4 尚未实施，且调试需求是「随手可点、不污染玩家设置界面」。

**取舍记录**：检测间隔（1 小时）与写入冷却（3 天）**刻意分开**——检测便宜、可以密；写入有副作用、必须稀疏。将来若要更省，只需调大 `REFRESH_INTERVAL_TICKS`，不必动冷却。
