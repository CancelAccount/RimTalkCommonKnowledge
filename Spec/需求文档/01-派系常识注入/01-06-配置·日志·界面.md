### FR-7 配置项（ModSettings）

| 设置项 | 默认 | 说明 |
| --- | --- | --- |
| `enableInjection` | `true` | 总开关；关闭后 `StartedNewGame` / `LoadedGame` 均不写入 |
| `enableBackfillOnLoad` | `true` | 读档校正开关（D4 / FR-11）：缺失则补、陈旧则重写、一致则不动 |
| `enablePeriodicRefresh` | `true` | 运行中定时校正开关（FR-11）；关闭后仅在新档 / 读档校正 |
| `refreshIntervalHours` | `1` | 定时校正间隔（游戏小时），换算为 `REFRESH_INTERVAL_TICKS`（1 小时 = 2500 tick） |
| `goodwillRefreshThreshold` | `10` | 好感度重写阈值：差异**仅**来自好感度且未达此值时不为纯数值波动重写（FR-11） |
| `includeIdentity` | `true` | 写入「基础身份」段 |
| `includeIdeology` | `true` | 写入「意识形态」段（无 Ideology DLC 时自动失效） |
| `includeRelation` | `true` | 写入「与我方关系」段 |
| `includeSettlements` | `true` | 写入「领袖与据点」段 |
| `knowledgeImportancePlayer` | `0.95` | **我方派系**条目的重要度（0\~1，滑条）。对齐社区库顶级档；`0.96\~1.0` 留给系统级，本 mod 不占（D43） |
| `knowledgeImportanceOther` | `0.80` | **其它派系与异种人**条目的重要度（0\~1，滑条）。对齐社区库「派系本体」档，避免压过同派系的社区条目（D43） |
| `categoryAlwaysLore` | `true` | 强制 `category = KnowledgeEntryCategory.Lore`（世界观）。关闭则退化为按 `tag` 自动猜分类，实测会落到「其它」（证据 ⑦） |
| `includeXenotypes` | `true` | 是否写入**独立的异种人常识**条目（FR-9）。无 Biotech DLC 时自动失效 |
| `includeFactionXenotypeRefs` | `true` | 是否写入**双向引用**：派系条目的第 ⑤ 段（成员构成）+ 异种人条目的「出没派系」段（D13） |
| `xenotypeGeneCount` | `4` | 异种人常识里列出的「标志性基因」条数（0 = 不写基因段） |
| `enableVerboseLog` | `false` | 输出逐派系明细日志（默认仅输出汇总与计数；Debug 包不受本项影响、恒输出明细） |
| `showCompositionInFactionUi` | `true` | **派系界面增强**（FR-14）：在派系列表悬停提示与派系信息卡追加「实际成员」构成。与常识注入互不影响，关闭后仅界面不再追加 |
| `enableKnowledgeUiOptimization` | `true` | **常识库界面滚动优化**（FR-15 / D48）：上游常识库对话框每帧绘制列表内**全部**条目（其虚拟列表建而未用），条目成千后滚动卡顿。开启后本 mod 只绘制滚动视口内的条目；关闭则恢复上游原始行为。与常识注入互不影响 |

- 设置类继承 `ModSettings`，`ExposeData` 全部字段（RimWorld 约定）。
- 设置界面由 `Verse.Mod` 子类 `FactionInfoMod` 提供（`SettingsCategory()` 返回 `MOD_SETTINGS_CATEGORY`，非空才出现在「选项 → Mod 设置」列表；见 FR-14）。设置页分「注入时机 / 派系内容段 / 重要度（我方 / 其它两个滑条）/ 异种人 / 日志 / 界面增强」六组，内容高于可视区时整页滚动。**预设库导入的两项开关**（`enableKnowledgeBaseImport` / `enableBuiltinKnowledgeImport`）随该需求迁至 [04-社区包导入.md](../04-社区包导入.md)（FR-6），仍落在「注入时机」组。
- 设置界面提供「立即对当前存档重新注入」按钮（开发/调试用，仅当 `Current.Game != null` 时可用）——便于改完设置立刻看效果，无需重开档；另提供「打开常识管理页面」按钮（FR-16 / [03-常识管理页面.md](../03-常识管理页面.md)）。
- 所有默认值与常量集中在一个 `FactionKnowledgeConfig` 静态类中，**不在业务代码里写字面量**。关键常量：`DEFAULT_IMPORTANCE_PLAYER = 0.95f`、`DEFAULT_IMPORTANCE_OTHER = 0.80f`（D43）、`FACTION_CONTENT_PREFIX = "【派系】"`、`XENOTYPE_CONTENT_PREFIX = "【异种人】"`。
- **定义原文让位（D43）**不在设置页暴露开关：它由「社区库是否已覆盖该 Def」自动决定（`RimTalkMemoryBridge.HasExternalEntryForTag`，判定键 = `FactionDef.LabelCap` / `XenotypeDef.LabelCap`，并排除本 mod 自身条目）。理由是它是「避免与社区常识重复」的口径修正，不需要玩家决策；两个重要度滑条仍保留，供玩家按喜好压高 / 压低本 mod 条目的排序位次。

### FR-8 日志与调试

- 全部日志为**中文**，统一前缀 `[派系常识]`。
- **汇总级**无条件输出（`Log.Message`），一次进入游戏至多三条：
  1. **mod 构造期（主菜单阶段，`FactionInfoMod(ModContentPack)` 被引擎反射实例化时）**输出启动横幅一次，表明本 mod 已被引擎加载，并报出本次运行是 **Debug 包还是 Release 包**（由编译符号 `DEBUG` 判定，与加载位置、开发者模式均无关）；进入存档后不再重复输出，例：`[派系常识] …：Release 包（发行版）。`
  2. 派系 / 异种人两侧各一条计数汇总，例：`[派系常识] 派系常识：候选 7 个，写入 6 条，跳过 1 条（内容一致），…`；定时轮询无写入时保持静默。
  3. 首次同步（新开档 / 读档）两侧跑完后补一条合计，例：`[派系常识] 常识注入完成：派系 6 条，异种人 4 条。`
- **明细级**（仅当 **Debug 包**，或 Release 包且 `enableVerboseLog` 为真时输出；与开发者模式无关）：**具体写入了哪些派系 / 异种人**及其完整内容，含写入、刷新、跳过、忽略四类，例：`已写入：{完整内容}`。Release 包未开此项时只保留上面三条汇总（条目总量与计数），不写具体内容。
- 异常一律 `Log.Error` 且**单个对象失败不中断整体**（逐个派系 / 逐个异种人 try/catch，且两类互相隔离）。

### FR-14 派系界面「实际成员」显示（Harmony 补丁，可开关）

**动机**：游戏自带的派系界面在 HAR 种族 / 兵种级异种人派系上会显示「智人种 100%」（原因此处与 FR-3 ⑤ / D41 同源，见证据 ㊷）。本项把本 mod 已有的「实际成员」口径**追加**到派系界面，作为**可选增强**：默认开启，玩家可在「选项 → Mod 设置」中关闭。

**为什么用 Harmony（D42 修订 D10）**：派系界面的文本由引擎**属性 getter**产出，没有可用的事件 / `GameComponent` 钩子；D10「零 Harmony」只针对**常识注入路径**，本项属**界面增强**，故以两个最小化的属性 Postfix 补丁实现（不改变 D10 注入路径的零补丁前提）。

| 项 | 定案 |
| --- | --- |
| 补丁宿主 | ① `FactionDef.Description` 属性 getter——派系列表悬停提示（`FactionUIUtility` 两处 tooltip + `WorldFactionsUIUtility` + `Dialog_RewardPrefsConfig`）；② `Faction.GetReportText` 属性 getter——派系信息卡「描述」条目（`StatsReportUtility.DescriptionEntry(Faction)` → `Dialog_InfoCard`）（证据 ㊸） |
| 追加内容 | **只输出游戏自身看不出的部分**：含非人类人形种族（HAR / alien race）→ **对齐原版成员段排版**的名称块（着色标题行「成员种族:」+ 每行 `  - {种族名}`，**只列名称不写占比**——种族在 Def 层没有概率声明，`PawnKindDef.race` 是单一确定值）；否则派系级分布不可信 → `他们的成员涉及以下异种人：{异种人名}。`（**同样不写占比**——兵种级集合是无条件并集，同一异种人可能只出现在个别特殊兵种上，写占比会误导）；其余情形**返回 `null` 不追加**（游戏自带「成员异种人概率」已正确，再写只是噪声） |
| 追加位置 | 原文本末尾，以空行分隔（原文本为空时直接返回块，避免前导空行）；不改动原文本本身 |
| 开关 | 设置项 `showCompositionInFactionUi`，默认 `true`；关闭后两个补丁立即返回原值（`FactionCompositionUi.Enabled`，设置未载入时按「显示」处理） |
| 异常隔离 | 构建整体 try/catch（`FactionCompositionUi.BuildSafely`）：这两处属性**每帧都可能被 tooltip 触发**，异常会连累整个派系页并刷屏，故任何异常一律降级为「本次不追加」+ `WarnOnce`（RK-30） |

- **不依赖 `Faction` 实例**：`FactionDef.Description` 可能在无存档界面被访问，故构建器只读 `FactionDef` 级数据（`RaceKnowledgeBuilder` / `XenotypeKnowledgeBuilder` 新增 `FactionDef` 级重载）。
- **不影响常识注入**：常识内容取 `Def.description` **字段**（不经这两个属性，FR-3 ①），补丁不改注入内容，也不影响 `RimTalkMemoryBridge` 的查库与幂等判定。
- **Harmony 依赖**：运行时由 `brrainz.harmony` 提供（`About.xml` 已 `loadAfter`）；游戏自身 `Managed` 目录**不含** `0Harmony.dll`，编译期从工坊 HarmonyMod 引用、`Private=false`（证据 ㊺）。补丁集用独立 Harmony ID（`HARMONY_ID`）便于排查冲突。
- **外星种族只列名称、不写占比**：种族在 Def 层**没有概率声明**——`PawnKindDef.race` 是单一确定值（`Verse\PawnKindDef.cs` L248），`PawnGenOption` 只有 `kind` + `selectionWeight`（`RimWorld\PawnGenOption.cs` L33\~L37），`FactionDef` 无种族分布字段；种族占比只能由兵种权重**估算**或实测已生成成员，二者都不是权威人口占比，故**只列名称**。（异种人层倒是真有概率表：`PawnGenerator.XenotypesAvailableFor`，但那是**异种人**口径，且是 per-kind、返回共享静态字典，不在本项范围。）
- **排版对齐原版成员段**：种族块按 `(标题 + ":").AsTipTitle() + "\n" + 名称.ToLineList("  - ", false)` 拼装（原版范式见 `RimWorld\FactionDef.cs` L199 / L217\~L218；`AsTipTitle` = `Verse\ColoredText.cs` L351，`ToLineList` = `Verse\GenText.cs` L841\~L859），新增常量 `UI_COMPOSITION_MEMBER_RACES_TITLE` / `UI_LIST_ITEM_PREFIX`；前导空行仍由 `FactionCompositionUi.Append` 负责，故不存在空行偏差。

### FR-15 上游常识库界面滚动优化（Harmony 补丁，可开关）

**动机**：上游 RimTalk-Expand Memory 的常识库对话框（`Dialog_CommonKnowledge`）在条目量变大后滚动明显卡顿。**根因取证**（证据 ㊾）：该对话框把 `VirtualListView<T>` 建好却**从未调用其 `Draw`**，改为手写 `foreach` 逐行绘制**全部**条目；叠加每帧 `GetFilteredEntries` 全表 `Where().ToList()` 与 `GetCategoryCount` 6 次全表扫描（含 `ToLower` 字符串分配）。IMGUI **无自动裁剪**，被遮住的行照样执行完整绘制，故条目越多越慢。同一作者在 `ITab_Memory` 写法正确（`SetItems` + `Draw`），属**实现疏漏**。

**为什么用 Harmony**：卡顿点在上游对话框内部，没有可用的公开钩子；本项属**界面增强**，与 D10「常识注入路径零 Harmony」的口径不冲突（同 D42 / FR-14 的口径收窄）。本项**不重写上游 UI、不改其控件与写路径**，只补上其漏掉的裁剪。

| 项 | 定案 |
| --- | --- |
| 补丁宿主 | ① `Dialog_CommonKnowledge.DrawCenterList(Rect)` 的 Prefix——每帧进入列表绘制前，记下滚动视口顶部（`listScrollPosition.y`）与底边（`+ rect.height - UPSTREAM_UI_VIEWPORT_PADDING`，对应上游 `GenUI.ContractedBy(rect, 5f)`）；② `Dialog_CommonKnowledge.DrawEntryRow(Rect, CommonKnowledgeEntry)` 的 Prefix——行矩形完全落在视口外时返回 `false`（跳过该行绘制） |
| 应用方式 | **运行期手动挂**（`CommonKnowledgeUiOptimization.TryApply(harmony)`，`FactionInfoMod` 构造期调用）：目标位于上游程序集，不能靠 `PatchAll` 静态标注；且必须在**任一上游私有名缺失时安全跳过**，故用 `AccessTools` 解析后手动 `Patch` |
| 依赖的上游私有名 | `DrawCenterList` / `DrawEntryRow` / `listScrollPosition`（常量集中在 `FactionKnowledgeConfig`：`UPSTREAM_UI_METHOD_DRAW_CENTER_LIST` / `UPSTREAM_UI_METHOD_DRAW_ENTRY_ROW` / `UPSTREAM_UI_FIELD_LIST_SCROLL_POSITION`） |
| 裁切口径 | 行矩形是**内容坐标**（`y` 从 0 起、不随滚动变化），故直接与视口内容边界比较；上下各留一行高的余量 `UPSTREAM_UI_CULL_MARGIN = 70f`（= 上游行高），避免边缘行闪烁 |
| 开关 | 设置项 `enableKnowledgeUiOptimization`，默认 `true`；关闭后进入时 `viewportKnown = false`，两个 Prefix 立即放行（`CommonKnowledgeUiOptimization.Enabled`，设置未载入时按「开」处理） |
| 异常隔离 | 两个 Prefix 内部整体 try/catch，异常一律降级为「本次不裁剪 / 不跳过」；应用期任一私有名缺失即 `WarnOnce`（`LOG_KEY_COMMON_KNOWLEDGE_UI_PATCH_FAILED`）并**整体放弃**，退回上游默认行为 |

- **不改数据与交互**：本补丁只跳过**视口外行**的绘制，条目的点击选中、分类筛选、搜索、增删改全部走上游控件与写路径，逐字不变。
- **与 D28 的关系（已修订）**：本补丁仍复用上游界面，只补上其漏掉的裁剪；D28「不实施自带 UI」已由 **D49 / FR-16** 放开——另建了本 mod 自己的常识管理页面（见 [03-常识管理页面.md](../03-常识管理页面.md)）。两者互补：本补丁让上游界面滚动不卡，自建页面解决滑块过短与按来源定位。
- **与 D42 / FR-14 的补丁集共用同一 Harmony ID**（`HARMONY_ID`），便于统一排查冲突。
