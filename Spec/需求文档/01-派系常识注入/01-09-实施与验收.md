**目录约定**

- **按职责分文件夹、命名空间保持扁平**：全部类型统一在 `RimTalkCommonKnowledge` 命名空间下（工程规模小，分层命名空间只增加 `using` 噪音）。子文件夹仅作物理归档，**移动文件不影响任何 `using`**；新增文件按上表归位。
- **`KnowledgeBase/` 是运行时数据目录、不是引擎加载目录**：RimWorld 只从 `Defs` / `Patches` / `Languages` / `Textures` / `Sounds` / `Assemblies` 等标准目录加载内容，`KnowledgeBase/` 不在其列，故不会被当游戏内容加载，本 mod 在运行时按已启用 packageId 读取。**只有放进这个目录的数据才会随包发放**（`Tools/` 在打包白名单之外）。
- SDK 风格 csproj 用默认 glob 收集 `**/*.cs`，无需为新增文件夹改 csproj。

**csproj 要点**

- `TargetFramework` = `net48`（同其它 mod 工程口径）；`Private=false` 引用（不复制上游 dll 进 Assemblies）。
- 引用：`Assembly-CSharp`、`UnityEngine.CoreModule`（`Mod.DoSettingsWindowContents(Rect)` 需要，Rect 属该程序集）、`UnityEngine.TextRenderingModule`（`Widgets.ButtonText` 的 1.6 重载含 `TextAnchor?` 可选参数，重载解析需要该类型信息）＋ `RimTalkMemoryPatch` ＋ `0Harmony`（FR-14 补丁需要）。
- 路径属性集中声明，不散落字面量：

```xml
<PropertyGroup>
  <RimWorldDir>..\..\..\..\</RimWorldDir>
  <ManagedDir>$(RimWorldDir)RimWorldWin64_Data\Managed\</ManagedDir>
  <Workshop294100>$(RimWorldDir)..\..\workshop\content\294100\</Workshop294100>
  <RimTalkMemoryDir>$(Workshop294100)3608181242\1.6\Assemblies\</RimTalkMemoryDir>
  <HarmonyDir>$(Workshop294100)2009463077\Current\Assemblies\</HarmonyDir>
</PropertyGroup>
<ItemGroup>
  <Reference Include="UnityEngine.CoreModule">
    <HintPath>$(ManagedDir)UnityEngine.CoreModule.dll</HintPath>
    <Private>false</Private>
  </Reference>
  <Reference Include="UnityEngine.TextRenderingModule">
    <HintPath>$(ManagedDir)UnityEngine.TextRenderingModule.dll</HintPath>
    <Private>false</Private>
  </Reference>
  <Reference Include="RimTalkMemoryPatch">
    <HintPath>$(RimTalkMemoryDir)RimTalkMemoryPatch.dll</HintPath>
    <Private>false</Private>
  </Reference>
  <Reference Include="0Harmony">
    <HintPath>$(HarmonyDir)0Harmony.dll</HintPath>
    <Private>false</Private>
  </Reference>
</ItemGroup>
```

- **Harmony 程序集来源**：游戏自身 `RimWorldWin64_Data\Managed` **不含** `0Harmony.dll`，须从 HarmonyMod 工坊（`2009463077\Current\Assemblies\`）引用；`Private=false` 不复制进本 mod `Assemblies`，运行时由 `brrainz.harmony` 提供（证据 ㊺）。

- **输出目录按配置隔离（出包流水线前提，见 `rimworld-mod-release` 技能）**：`Release → ..\Assemblies`（入库）、`Debug → ..\AssembliesDebug`（`.gitignore` 忽略），另配 `AppendTargetFrameworkToOutputPath=false`（否则会多出 `net48\` 一层）与 `IncludeSourceRevisionInInformationalVersion=false`（dll 字节只由源码决定，跨 commit 可复现）。**不再用 `AfterTargets="Build"` 复制**——那会让 Debug 编译覆盖入库的发行 dll。
  - 副作用（须知晓）：游戏只读 `1.6\Assemblies`，故 F5 调试产出的 `1.6\AssembliesDebug\*.dll` **不会**自动生效；游戏内试跑要么走正式打包，要么手工把该 dll 拷入 `1.6\Assemblies`。这是「调试 dll 永不污染发行 dll」的代价。

**打包流水线**（`Tools\Build-Release.ps1`，复制自 `rimworld-mod-release` 技能模板）：

- 一次运行完成：读 `modVersion` → 工作区脏 / 同名 tag 告警（不阻塞）→ 依次编译 Release、Debug → 按白名单组装 `dist\stage\{release,debug}\RimTalkCommonKnowledge\` → Debug 包改写包内版本号为 `<版本>-debug` → 产出两个 zip。
- 本 mod 的配置取值：`PackageName` / `AssemblyName` = `RimTalkCommonKnowledge`；`GameVersionDir` = `1.6`；`IncludeDirs` / `RequiredDirs` = `@('About', 'KnowledgeBase')`（`KnowledgeBase` 为随包常识库数据，必须进包）；`IncludeRootFiles` = `@('LoadFolders.xml')`；`ExcludeRelativeDirs` = `@('1.6\Source', '1.6\AssembliesDebug')`（防御性，当前 `1.6` 不在白名单、dll 由脚本单独放入）；`ExcludeFilePatterns` 空。
- 用法：`powershell -ExecutionPolicy Bypass -File Tools\Build-Release.ps1`（仅打包）；加 `-CreateRelease` 则再调 `gh` 建 GitHub Release（**须先 `git push`**，否则 tag 指向远程旧 commit）。
- `Tools\` 下 ps1 必须存为 **UTF-8 with BOM**，否则 PowerShell 5.1 按 GBK 解码中文注释会报一堆假语法错误。
- 尚未发布到创意工坊，**包内不含 `About\PublishedFileId.txt`**；首次上传工坊前须先由游戏「上传」动作生成该文件并入库，否则工坊会新建条目。
- `About.xml` 已补 `<modVersion>2026.10.03</modVersion>`：版本号唯一人工编辑点，zip 名 / tag / Release 标题均由脚本从此派生。

**About.xml 已补**：

- `<loadAfter>`：`brrainz.harmony`、`cj.rimtalk`、`cj.rimtalk.expandmemory`（已加）
- `modDependencies` 保持 `cj.rimtalk.expandmemory`（已是硬依赖）
- **不要**把可选共存 mod 写进 `modDependencies`

**LoadFolders.xml**（已建）：`<v1.6><li>/</li><li>1.6</li></v1.6>` —— 根目录（About / Languages / Defs）恒加载，`1.6` 目录随版本加载。

## 9. 验收标准

### 9.1 派系常识

1. **新档**：开局后 RimTalk 常识库（`RimTalk_Memory` 主标签页）中出现每个有效派系各 1 条 `【派系】…` 条目，**分类显示为「世界观」**。
2. **重要度分档**：任取一条**普通派系**常识，其 `importance` 为 **0.80**（D43）、`category` 为 `KnowledgeEntryCategory.Lore`（UI 归入「世界观」）；**我方派系**条目为 **0.95**；`【异种人】` 条目为 **0.80**。把设置里两个滑条调低后重注入，条目重要度随之变化。
3. **内容正确性**：随机抽 2 个派系，条目中的派系类型、科技水平、关系种类、据点数量与世界地图实际一致。
4. **触发有效性**：在 RimTalk 标签测试工具中输入含某派系名的对白文本 → 该派系常识被匹配到，且在注入结果中排序靠前（权重对齐社区库档位）。对**以某非基础异种人为主**的派系，输入**只含该异种人名**的文本，同样能匹配到该派系常识（D17）。
5. **幂等**：同一存档连续读档 3 次，条目数量不增长。
6. **旧档补齐**：对一个「装本 mod 之前就已存在」的存档读档后，常识库被补齐。
7. **降级**：关闭总开关后重开档，常识库无 `【派系】` 条目；卸载本 mod 后上游功能不受影响。
8. **无 Ideology DLC**：不报错，意识形态段自动缺席，其余段正常。
9. **仅有玩家派系场景**：某些剧本下只有一个玩家派系（无其它有效派系）时，写入**我方派系 1 条**（FR-13）且不报错。

### 9.2 异种人常识（需 Biotech）

10. **集合正确性**：新档后把日志中的异种人清单与「有效派系的 `FactionDef.xenotypeSet` ∪ 其主理念 `MemeDef.xenotypeSet` ∪ 各兵种 `PawnKindDef.xenotypeSet`（再按 `BaselinerChance` 补基础异种人）」逐一对照，**不多不少**（D40）。
11. **内容与基因顺序**：任取一条 `【异种人】…` 条目，其「标志性基因」列表与游戏内该异种人信息卡上按「类别优先级降序 → 类别内顺序升序」排列的**前 N 个非 Miscellaneous 基因**一致（`N = xenotypeGeneCount`，默认 4）；`xenotypeGeneCount = 0` 时该段整体缺席。
12. **基础异种人**：`XenotypeDefOf.Baseliner`（中文「智人种」）条目存在，其基因段写「没有任何特殊基因，是自然演化的人类」而非空白。
13. **双向引用自洽**：任取一个派系条目，其第 ⑤ 段列出的异种人，其条目「出没派系」段必含该派系；反之亦然（互相印证，无单向悬空引用）。
14. **无 Biotech DLC**：不报错、无 `【异种人】` 条目，且派系条目第 ⑤ 段缺席，其余段正常（与第 8 项相互独立）。
15. **异种人开关**：关闭 `includeXenotypes` 后无 `【异种人】` 条目但派系条目第 ⑤ 段仍在；关闭 `includeFactionXenotypeRefs` 后两处引用段均缺席；连续读档 3 次条目数不增长（幂等）。

### 9.3 全局

### 9.4 我方派系介绍（FR-13）

18. **条目存在**：新档 / 读档后常识库中存在一条内容形如 `【派系】「{我方派系名}」是我们自己所属的派系。…` 的条目，其 `category` 为「世界观」、`importance = 0.95`。
19. **内容正确性（有 Odyssey）**：条目中的据点名与世界地图我方据点**一一对应且全部列出**；若有逆重飞船，飞船名与游戏内一致，停留时长与世界地图/飞船信息一致。
20. **读不到时省略**：飞船停靠在已有地图（读不到着陆时刻）时，内容降级为「我们有一艘逆重飞船「…」。」**不出现编造的时长**。
21. **降级（无 Odyssey）**：无 Odyssey DLC 时不报错，飞船段整体缺席，其余段（身份 / 据点 / 建立时长 / 财富）正常。
22. **质变与冷却**：新增或摧毁一处我方据点（或新增/移除飞船）→ **立即**重写；仅财富或时长增长 → 3 天内不重写、满冷却后重写。连续读档 3 次条目数不增长（幂等）。
23. **财富口径**：条目中的财富值与「主基地地图」的财富面板一致（非全据点合计）。
24. **新档无报错**：创建新档时日志中**不出现** `Tried to get relation between faction … and itself.`，也不出现 `GoodwillSituationManager.GetMaxGoodwill` 的 `NullReferenceException`（RK-22）。
25. **财富读失败可降级**：当地图存在未登记地形导致 `WealthTotal` 越界时，我方派系条目**仍然写入**（只缺 ⑤ 财富段），且日志只出现一次「读取主基地财富失败…」告警（RK-23）。
26. **轮询不刷屏**：开启明细日志（Debug 包，或 Release 勾选 `enableVerboseLog`）后空跑若干游戏小时，日志中**不再**逐小时出现「跳过（非质变改动，覆写冷却中）」（RK-24）。
27. **人口段正确**：条目中殖民者 / 临时成员 / 囚犯 / 奴隶 四类人数与游戏内实际一致（殖民者含外派商队者，不含动物 / 机械体 / 尸体）；附加子句**只列非零类别**，四类中仅殖民者非零时整句只有殖民者数。
28. **人口质变口径**：招募 / 死亡 / 捕获一名殖民者或奴隶 → **立即**重写；囚犯增删、难民 / 来客来去 → 不立即重写，走 3 天冷却（D34）。
29. **无 DLC 降级**：无 Ideology / Biotech 时人口段照常输出且不报错（奴隶数恒为 0）；无 Odyssey 时仅飞船段缺席。
30. **改名不留残条（D35）**：开档后用改名界面把玩家派系从「新移民」改成新名 → 库里**只有一条**我方派系条目，标签与内容均为**新名**；提到旧名「新移民」**不再命中**；提到新名仍能命中。
31. **飞船名进标签（D35）**：建成逆重飞船（Odyssey）后，我方派系条目**立即**重写，标签变为「派系名,飞船名」，内容含飞船段；殖民地提到飞船名能带出该条目。飞船改名后标签与内容同步更新，仍只有一条。
32. **机械族型号段（D37）**：有 Biotech 且拥有友方机械族时，条目 ③ 段**按型号列出**「N 台某型」（如「3台清扫机、2台建造者」），台数与型号与游戏内一致，且**不出现**「失去监管」子句；无机械族时写「我们目前没有友方机械族」；无 Biotech 时该段整体缺席。
33. **气候段（D36）**：条目 ⑤ 段写出主基地所属生物群系名，与世界地图的「生物群系」一致；尚无主基地地图时该段缺席。
34. **开局剧本句（D38）**：条目 ① 身份句之后写出本局剧本名（如「迫降」「失落的部落」），与剧本界面所选一致；读不到剧本时该句缺席；切换语言后该句随冷却重写为对应语言。

### 9.5 隐藏派系注入（D39）

35. **隐藏派系纳入**：新档后常识库中存在原版机械族 / 虫族等隐藏派系的 `【派系】…` 条目（每条 `category` 为「世界观」、`importance = 0.80`）；mod 自带的世界观隐藏派系同样被注入。
36. **不写隐藏派系没有的数据**：上述条目的内容中——**不出现**关系句与好感度句、**不出现**「目前没有已知的领袖」、**不出现**「科技水平为Undefined」；有意识形态 / 成员构成的隐藏派系才写对应段，无者整段缺席。日志中**不出现**引擎 `has null relation with` 的 `Log.Error`（③ 段前置 `HasGoodwill` 守卫 + 指纹取固定键 `NoRelation`）。
37. **降级不误伤普通派系**：非隐藏派系（可谈关系、有自定义名、有领袖）的条目内容与本次改动前**逐字一致**（关系句、好感度句、「没有已知的领袖」句照常出现）。

### 9.6 异种人来源口径修订（D40）

38. **兵种级来源覆盖**：对「派系级未声明 `xenotypeSet`、特色异种人只写在 `PawnKindDef` 上」的派系（如成员混编机械族的 mod 派系），日志中的异种人清单**包含**其兵种级异种人；常识库中存在该异种人的 `【异种人】…` 条目，且其「出没派系」段含该派系名；该派系条目的 `tag` 含该异种人名。
39. **不再误报「智人种 100%」**：上述派系的派系条目**第 ⑤ 段缺席**，日志出现「跳过成员构成段（派系级异种人分布不可读）」明细；对照游戏内该派系实际刷出的成员，异种人与其兵种级设置一致。
40. **原版派系不受误伤**：派系级声明了 `xenotypeSet`、且无兵种级覆盖的原版派系（部落 / 外来者 / 帝国等），成员构成段**照常输出**且与本次改动前**逐字一致**。

### 9.7 成员种族口径（D41）

41. **HAR / alien race 派系写出成员种族**：对成员含非人类人形种族的派系（如米莉拉），其派系条目第 ⑤ 段为 `他们的成员包括{种族名}。`，**不出现**「智人种 100%」等异种人内容；该派系条目的 `tag` 含该种族名（唯一成员种族时）。
42. **不误伤人类派系**：成员均为人类的派系（部落 / 外来者 / 帝国等）**不出现**种族句，第 ⑤ 段仍按异种人口径输出，与本次改动前一致。

### 9.8 派系界面「实际成员」显示（FR-14）

43. **默认追加**：未改设置时，把鼠标悬停到 HAR 种族派系（如米莉拉）的派系列表行 → 悬停提示末尾出现本 mod 追加的**成员种族块**（着色标题行「成员种族:」+ 每行 `  - {种族名}`，**只有名称、无百分比**，与原版「成员异种人概率」段排版一致）；点开该派系信息卡 → 「描述」条目末尾同样出现该块。
44. **不重复、不误伤**：对派系级异种人分布正常的原版派系（部落 / 外来者 / 帝国），悬停提示与信息卡的**文本与本次改动前逐字一致**（不追加任何内容）。
45. **开关生效**：在「选项 → Mod 设置 → RimTalk 常识+」中关闭「在派系界面显示实际成员构成」后，上述两处**均不再**出现追加句；重新打开后恢复（无需重开档）。
46. **异常降级**：补丁构建过程若抛异常，界面**不崩、不刷屏**，仅在日志出现一次告警（RK-30）。

### 9.9 重要度分档与「定义原文」让位（D43）

47. **定义原文让位**：导入社区常识库后，对社区库**已覆盖**的 Def（如原版「野蛮的部落」「机械主巢」，社区异种人「初鼠种」）——本 mod 对应条目**不含**该 Def 的定义原文句（派系 ① 的 `{描述}。` / 异种人 ① 的 `：{description}`），但**仍含**运行时动态段（派系 ②\~⑤、异种人 ②③）；对社区库**未覆盖**的 mod 派系 / 异种人，条目**照常写全**（含定义原文）。
48. **查重不误判自身**：隐藏派系（实例名 = `def.LabelCap`，如「机械主巢」）的条目在连续读档 3 次后内容**不抖动**——不会因把本 mod 自己的条目误判为「社区已覆盖」而在「含 / 不含定义原文」之间来回切换（查重按内容前缀 `【派系】` / `【异种人】` 排除自身条目）。
49. **让位可达动态段**：让位仅影响定义原文，条目触发与注入照常——输入含该派系名的对白文本，仍能匹配到条目并注入其动态段内容。

### 9.10 常识库界面滚动优化（FR-15 / D48）

50. **滚动不卡**：常识库条目上千条时，打开「常识库」对话框滚动列表，滚动帧率明显提升（不再逐帧绘制全部条目）。
51. **可见区完整**：滚动到任意位置，视口内条目**照常完整绘制**（含上 / 下边缘附近的行，因留了一行高的裁切余量 `UPSTREAM_UI_CULL_MARGIN`，不出现边缘行闪烁或空行）。
52. **功能无损**：条目的点击选中、分类筛选、搜索、增删改（走上游控件与写路径）与改动前**逐字一致**——本补丁只跳过视口外行的绘制，不触碰任何数据与交互逻辑。
53. **开关生效**：在「选项 → Mod 设置 → RimTalk 常识+」中关闭「优化常识库界面滚动」后，界面**恢复上游原始行为**（每帧绘制全部条目）；重新打开后恢复裁剪（无需重开档）。
54. **异常降级**：上游三个私有名（`DrawCenterList` / `DrawEntryRow` / `listScrollPosition`）任一缺失（上游结构变更）时，补丁**整体放弃**并在日志出现一次告警，界面**不崩、不刷屏**、退回上游默认行为。
