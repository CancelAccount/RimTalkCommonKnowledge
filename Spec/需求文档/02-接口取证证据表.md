| `AddKnowledge` 与 `AddKnowledgeEx` 只是后者能多传参，行为等价 | **不等价**。`AddKnowledge` 完全不写 `canBeExtracted` / `canBeMatched`，两开关停留在侧表默认 **false**（条目既不提供链式线索、也不能被链式命中）；要开启必须用 `AddKnowledgeEx` | 证据 ㉘ |
| 条目要被匹配到必须开 `canBeMatched` | 只对**链式轮（第 2 轮起）**成立。第 1 轮是「对白文本直接匹配」，入选条件里 `!isChaining` 已短路，**不受 `canBeMatched` 限制**——所以默认 false 的条目照样能被对白直接匹配到 | 证据 ㉘ |
| `canBeExtracted` / `canBeMatched` 是 `CommonKnowledgeEntry` 的字段 | 不是。它们在 `ExtendedKnowledgeEntry` 侧表里（按 `entry.id` 索引、随存档单独序列化），`CommonKnowledgeEntry` 上既无字段也无属性 | 证据 ㉘ |
| `TaggedString` 可以直接当 `string` 用，包括传进 `string.Format` | **半对**。`implicit operator string` 实现为 `RawText.StripTags()`（剥标签），但**只在目标类型明确为 `string` 时生效**；传进 `string.Format(..., object)` 会**装箱**走 `ToString()`，而它**只返回 `RawText`（带富文本标签）**。故 `LabelCap` / `NameFullColored` 必须先赋给 `string` 局部变量，否则颜色标签会混进常识内容 | 证据 ㉙ |
