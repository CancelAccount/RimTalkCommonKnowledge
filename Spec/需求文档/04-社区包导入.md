## 1. 诉求与现象

| 场景 | 现状（改前） | 期望 |
| --- | --- | --- |
| 不同 mod 的派系设定差异大 | 逐 mod 手写预设清单必然滞后 | 由随包**社区常识库**数据驱动，按已启用 mod 自动适配 |
| 只订阅某族本体、未订阅其扩展 | 块级粒度把本体与扩展同块混装，扩展内容被全量注入 | 逐文件按 `packageId` 判定，只导玩家真正启用的部分 |
| 游戏本体 / 公共常识 | 与 mod 条目混在一起 | 独立开关控制，默认不导（体量大） |
| 汉化包 | 单独查自身 `packageId` 会漏 | 并入其本体，共用本体 `packageId` |

## 2. 机制

- **预设库 = 随包数据**：`KnowledgeBase/mod层导入包-<版本>/`（60 块目录 / 335 文件，每模组一文件 `<块>/<模组名>.txt`，另有块级 `_公共.txt` 与 `本体-<DLC>.txt`）+ `KnowledgeBase/模组溯源映射.tsv`（「块名 / 模组名 → `packageId`」二级索引，由 `Tools/常识库/Build-ModSourceMap.ps1` 生成）。
- **导入通道**：`CommonKnowledgeAPI.ImportFromText(text, clearExisting: false)`——上游公开 API，接受块文件原格式 `[标签|重要度|匹配模式|可提取|可匹配]·[类别] 内容`。该 API **纯追加、零去重**，故差集必须本 mod 自建；`clearExisting` 恒为 `false`（传 `true` 会清空玩家整个常识库，证据 ㊼）。
- **导入粒度（逐文件三档门槛，D47）**：模组文件按已启用 `packageId`；`本体-<DLC>.txt` 按实际持有 DLC；`_公共.txt` 块内含有模组文件时按「任一模组命中即导」，否则随本体开关。
- **`KnowledgeBase/` 是运行时数据目录、不是引擎加载目录**：RimWorld 只从 `Defs` / `Patches` / `Languages` / `Textures` / `Sounds` / `Assemblies` 加载内容，本目录由本 mod 在运行时按需读取（详见 [01-09 §7](01-派系常识注入/01-09-实施与验收.md#7-工程结构)）。

| 对象 | 现状 | 结论 |
| --- | --- | --- |
| 上游导入通道 | `ImportFromText` 纯追加零去重 | 差集须本 mod 自建（证据 ㊼） |

## 4. 功能需求（FR-6）与导入口径

**主路径（数据驱动，D20 / D47）**

- 运行时读 `模组溯源映射.tsv`，按**当前已启用 mod 的 `packageId`** **逐文件**判定：命中即把该模组文件内的条目**原样导入**常识库（导入 = 写入 `tag` / 内容 / 重要度，不做改写）。
- 与本 mod 自建条目的关系原由 D43② 处理（社区已覆盖该 Def 时让出「定义原文」段）；**D57（2026-10-09）已关闭让位**——社区条目内容同样取自 Def，本 mod 描述节恢复写全；置 `ENABLE_DEF_DESCRIPTION_DEFERRAL = true` 可恢复本行为。
- 索引列出而包内缺失的条目文件、包内存在而索引缺行的模组文件、一个 `packageId` 命中多块等情况经 `KnowledgeLog` 输出告警。

**导入口径（D44 / D45）**

- **时机**：只在新档 `StartedNewGame` 与读档 `LoadedGame` 填充，不入定时校正（社区条目为静态数据）。
- **判重与补回（D45）**：判重键 = **`tag` + 内容**（同一 `tag` 可有多条，仅按 `tag` 判重会让同 tag 的后续条目永远进不来）；取库内已有条目的键集合做差集，只导入**缺失的整行**。玩家手动删除的条目下次新档 / 读档会补回（与 [01-08 D22](01-派系常识注入/01-08-决策表.md) 一致的已知行为）。
- **重要度**：沿用社区条目**原始重要度**，不套用 D43 的两档覆盖（D43 只约束本 mod 自建条目）。
- **筛选粒度（逐文件，D47）**：① **模组文件**`<块目录>/<模组名>.txt`——按已启用 `packageId` 逐文件判定（比较大小写不敏感、去 `_steam` 后缀）；② **块级通用面** `_公共.txt`——块内含模组文件时按「**任一模组命中即导**」，本体块 / 纯公共块随本体开关；③ **游戏本体** `本体-<DLC>.txt`（`Core` / `Royalty` / `Ideology` / `Biotech` / `Anomaly` / `Odyssey`）——按玩家**实际持有 DLC** 取用，`Core` 恒真，由本体开关控制。
- **汉化包并入本体**：汉化包条目与其本体共用同一 `packageId`（映射表由 `Tools/常识库/Build-ModSourceMap.ps1` 自动反查并入），故只订阅本体的玩家也会导入汉化包条目；两侧同 `tag` 不同文的内容按「`tag` + 内容」键各自留存。

**配置项（FR-7 中属本页的两项）**

| 设置项 | 默认 | 说明 |
| --- | --- | --- |
| `enableKnowledgeBaseImport` | `true` | **预设库导入开关**（FR-6 / S8 / D44 / D47）：开启时在新档 / 读档把 `KnowledgeBase/` 中**已启用 mod 对应**的条目文件（逐文件按 `packageId` 判定，连同该块的 `_公共.txt` 通用面）导入常识库；关闭后本路径不写入 |
| `enableBuiltinKnowledgeImport` | `false` | **本体块导入开关**（S8 / D45 / D47）：是否一并导入游戏本体条目（`本体-<DLC>.txt`，**只取已持有 DLC 对应部分**）与不依赖任何 mod 的公共块（如 `自定义常识`，体量较大）。默认关；与 mod 文件开关各自独立 |

**次路径（代码级扩展点，本期暂不落地 —— D46）**

以下接口 + 注册表**本期不建文件**：目前没有任何 mod 专属预设要用它，落地一个无调用方的骨架属死代码。待日后真出现「按 mod 定制模板」的需求时，再按下述形态抽出接口 + 注册表；下方说明仅为**未来形态参考**。

- `IFactionKnowledgePreset`（`Id` / `Matches(Faction)` / `Build(Faction)`）与注册表 `FactionKnowledgePresets`：按优先级从高到低询问 `Matches`，首个命中者接管；全部不命中则用内置 `DefaultFactionPreset`（即 [01-02 FR-3](01-派系常识注入/01-02-派系内容模板.md) 通用模板）。匹配依据（按可靠性排序）：`faction.def.modContentPack?.PackageId` → `faction.def.defName` 前缀 → `faction.def` 上的特征 `HediffDef`/`CompProperties`。
- **异种人侧同构**：并列接口 `IXenotypeKnowledgePreset`（`Id` / `Matches(XenotypeDef)` / `Build(XenotypeDef)`）与 `XenotypeKnowledgePresets`，默认实现 `DefaultXenotypePreset`。**为何两套接口而非一套**：本工程目标框架 .NET Framework 4.8 **不支持 C# 8 默认接口方法**，一个接口塞两个可选钩子会迫使每个预设实现无关方法。

## 5. 影响面与副作用

| 维度 | 影响 |
| --- | --- |
| 存档 | 导入的条目随存档自然保存（证据 ⑤）；不改原版 / 上游任何存档字段 |
| DLC | 本体文件按实际持有 DLC 取用（`Core` 恒真）；无 DLC 依赖到导入器本身 |
| 翻译 | 社区条目为中文文本；汉化包并入本体（D47） |
| 加载序 | 无新增依赖；`packageId` 比较忽略大小写并去 `_steam` 后缀 |
| 性能 | 导入是「读库 + 差集比对」的稳态操作，已存在条目零写入零日志；只在新档 / 读档执行 |
| 回滚 | 关闭两个开关即停用本路径（已写入条目留存属 D22 已知行为） |

**风险与护栏**

| # | 风险 | 护栏 |
| --- | --- | --- |
| RK-33 | 社区常识库含**模板残留条目**：`心情（游戏本体）` 块 **89 条**（占全库 0.35%，唯一 tag 73 个，全部 `matchMode=Any`）的 tag / content 是 **ThoughtDef 原文模板**（`人皮{0}`、`和{0}结婚`、`我的母亲{0}死了`）；上游匹配是**单向同串包含**（`上下文.IndexOf(tag)`）且解析不做占位符归一 → 运行时 `{0}` 已被人名替换，**这些条目在 tag 触发路径上永不命中**；其 content 同含 `{OTHERPAWN}` 之类占位符 | 只影响 tag 触发通道，且**不污染其它条目**（注入不报错、不误删）；其余 59 块为 0。若玩家开启上游「向量增强」通道（默认关、需自备云端 embedding），仍可能按内容语义被召回。本期**不处理**（[02 证据 ㊻](02-接口取证证据表.md)）；若日后要清，须在 `常识库·叙事.txt` 层剔除后重新分块，以维持分块包与叙事层两份同步 |
| RK-34 | 预设库导入（S8）的两项落地风险：① **规模与不可逆**——全库 60 块 25653 条，已启用 mod 通常命中数块（单块 20\~3000 条），写入后随存档保存，玩家手动删除会被下次读档补回（D22 / D44）；② **packageId 匹配**——`ModMetaData.PackageId` 可能带 Steam 后缀（`_steam`）且大小写不一，直接字符串比对会漏块 | ① 默认只导**已启用 mod** 的块，本体 17 块另有开关（默认关）；导入为**差集**——已存在条目零写入、零日志，稳态下每次读档仅「读库 + 比对」；想彻底停用可关 FR-7 两个开关。② 比较时忽略大小写并去 Steam 后缀（`ModsConfig.TryGetPackageIdWithoutExtraSteamPostfix` / `ModMetaData.SamePackageId(ignorePostfix: true)`）；漏块 / 一个 packageId 命中多块经 `KnowledgeLog.WarnOnce` 暴露（证据 ㊼） |

### 7.1 验收标准

1. **导入内容一致**：新档 / 读档后，`enableKnowledgeBaseImport`（默认开）对应的常识库出现**当前已启用 mod** 各条目文件的条目，内容与文件**逐字一致**、重要度沿用社区原值。
2. **逐文件判定**：只启用「某族本体」而未启用其扩展时，常识库**只出现本体文件的条目**，不出现该块内其它扩展 mod 的条目。
3. **幂等**：同一存档连续读档 **3 次条目数不增长**（判重键 = `tag` + 内容）。
4. **补回**：手动删除其中一条后再次读档**被补回**（D22 / D44）。
5. **开关生效**：关闭 `enableKnowledgeBaseImport` 后本路径不再新增写入（已有条目留存）。
6. **本体 / 公共块**：`enableBuiltinKnowledgeImport` 默认关时**无**游戏本体条目与纯公共块（`自定义常识`）；开启后出现「**仅已持有 DLC** 对应的 `本体-<DLC>.txt`」条目，且与 mod 文件开关互不影响。
7. **不一致告警**：索引列出而包内缺失的条目文件、包内存在而索引缺行的模组文件，各输出一次 `WarnOnce`（后者即「静默不导入」风险点）。
