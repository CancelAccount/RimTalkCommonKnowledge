## 1. 背景与目标

RimTalk-Expand Memory 提供了一套「常识库」：条目形如 `[标签|重要性]内容`，殖民者对白文本中出现标签子串时自动匹配注入（证据 ③）。但相关的世界设定需要玩家手工录入。

本 mod 在新开档时自动把世界地图上每个派系的客观设定、以及与该派系相关的异种人设定整理成常识写入该库，让殖民者一开口就"认识"这个世界的势力格局与种族构成。

**目标**：零手工录入，新档开局即拥有全部派系与其相关异种人的常识；旧档装上本 mod 也能补齐。

**与上游的分工**：上游 `PawnStatusKnowledgeGenerator` 已经会为每个殖民者写「个人状态」条目，其中含其种族与异种人（形如 `{殖民者}的种族是{种族名}-{异种人名}`，例：「小明的种族是人类-智人种」，证据 ㉖）。本 mod 写的是**世界级设定**（这个异种人是什么、有何标志基因、哪些派系由他们组成），二者互补，不重复。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 常识库 | RimTalk-Expand Memory 的 `CommonKnowledgeLibrary`，随存档保存（证据 ⑤） |
| 条目 / entry | `CommonKnowledgeEntry`：`tag`（触发标签）+ `content`（注入内容）+ `importance`（重要度 0\~1） |
| 派系常识 | 本 mod 注入的常识条目（内容前缀 `【派系】`），tag 为某派系名，或以半角逗号并列该派系的**唯一特征词**——优先成员种族名（D41），否则特征异种人名（D17） |
| 异种人常识 | 本 mod 注入的、`tag` 为某异种人名（`XenotypeDef.LabelCap`）的常识条目（内容前缀 `【异种人】`），需 Biotech DLC |
| 有效派系 | 通过 FR-2 筛选后、值得注入常识的派系 |
| 桥接类 | 本 mod 中唯一直接引用 `RimTalkMemoryPatch.dll` 的类（`RimTalkMemoryBridge`），隔离上游依赖 |

## 3. 功能需求

### FR-1 注入时机与生命周期

| 场景 | 钩子 | 行为 |
| --- | --- | --- |
| 新开档 | `GameComponent.StartedNewGame()` | 为全部有效派系注入常识（无论是否已存在同标签条目 → 先清理再写入，见 FR-5） |
| 读档 | `GameComponent.LoadedGame()` | 仅**补齐缺失项**：逐派系判定，已有则跳过，缺失则写入 |
| 切图 / 换档 / 读档重进 | 同 `LoadedGame()` | 同上（幂等） |

- 使用 `GameComponent` 子类，靠 `typeof(GameComponent).AllSubclassesNonAbstract()` 自动发现（证据 ⑪），**不需要 Def、不需要 Harmony**（D10）。
- 构造签名必须为 `public XxxComponent(Game game)`，且**不能**写 `: base(game)` —— `GameComponent` 自身没有 `(Game)` 构造，写了直接 **CS1729**；`Game` 参数只是为了匹配 `Activator.CreateInstance(type, this)`，基类走隐式无参构造（证据 ⑪，已编译验证）。
- 不在 `WorldComponent.FinalizeInit`、不在 `FactionGenerator` 补丁上做注入（D1 理由：玩家派系与玩家关系在那些时点尚不存在，证据 ⑩）。
- 全程不得在 `Current.Game == null` 或 `Find.World == null` 时调用常识库（证据 ②：`GetCommonKnowledge()` 在无 Game 时返回**游离的空库**，写进去会静默丢失）。
- **执行顺序**：同一次回调内先跑**派系**一遍（FR-2\~FR-5），再跑**异种人**一遍（FR-9）。异种人一遍依赖派系一遍的产物（FR-2 的有效派系集合 + 双向引用所需的派系名），故顺序不可颠倒。
- 两次旁路互相独立 try/catch：异种人一遍失败不得影响已完成的派系注入。

### FR-2 派系筛选

遍历 `Find.FactionManager.AllFactionsListForReading`（`List<Faction>`，内部列表引用，**只读遍历、不增删**，证据 ⑨㉓），按以下规则筛选：

| 筛选条件 | 成员 | 处理 |
| --- | --- | --- |
| 玩家派系 | `faction.IsPlayer` | **纳入**（[D33](#6-决策表) 修订 D2 原口径）：内容走**独立**模板（FR-13），不套用普通派系的五段 |
| 隐藏派系 | `faction.Hidden` | **纳入**（[D39](#6-决策表) 修订本条原口径）：机械族 / 虫族 / 古代人 / 实体等，以及 mod 自带的世界观隐藏派系（常是世界观的重要组成部分）。这类派系缺数据（无自定义名、无与玩家关系、无领袖、无意识形态），内容**逐段判缺跳过**，**不写引擎兜底值 / 不适用值**（见 FR-3） |
| 临时派系 | `faction.temporary` | **排除**（临时敌对/商队等，不构成世界格局） |
| 已覆灭派系 | `faction.defeated` | **不排除**：「已被我们打败的势力」本身是有价值的谈资；但若同时满足「据点数为 0」且「无领袖」，则视作空洞常识跳过，只在内容里保留一句「他们已被我们击败」 |

参考基线：同作者 `NewThreeKingdomsArt` 的 `MemeWeightApplier.InjectFactionNames` 仅排除 `IsPlayer` / `Hidden`（`Source/MemeWeightApplier.cs#L55-L62`）；本 mod **不再排除 `Hidden`**（D39：隐藏派系常是世界观的组成部分），相对基线只多一项 `temporary` 排除。

**同名派系**：按 `faction.Name` 归并；若两个派系同名，合并为一条内容（见 [§6 决策表](#6-决策表) D21）。

### FR-3 内容模板

每派系产出 1 条 entry（D6）。内容为**单行、无换行**（`ImportFromText` 按 `\n` 切行，换行会破坏导入导出格式，证据 ⑧），各段之间用中文句号串联。名字统一取 `faction.Name`（`HasName` 为假时回退 `def.LabelCap`，证据 ㉓）。

固定前缀 `【派系】` 兼作幂等标记（D8）。

| 段 | 模板 | 取值来源（均已核实 public） | 缺省处理 |
| --- | --- | --- | --- |
| ① 基础身份 | `【派系】{name}是一支{def.LabelCap}派系，科技水平为{tech}。{描述}。` | `Faction.Name` / `Faction.def.LabelCap` / `FactionDef.techLevel`→`TechLevelUtility.ToStringHuman()` / `FactionDef.description` | 身份句按数据判缺降级：`techLevel == TechLevel.Undefined` → **省略科技水平子句**（不写「科技水平为Undefined」）；名字与 `def.LabelCap` 同字（隐藏派系 `Name` 回退为 `def.LabelCap`）→ **省去「是一支 X 派系」**以免同义重复；`description` 为空 → 省略描述句 |
| ② 意识形态 | `他们信奉「{ideo.name}」，核心信条是{meme1}、{meme2}。` | `faction.ideos.PrimaryIdeo` / `Ideo.name`（公有字段） / `Ideo.memes`（`List<MemeDef>`，取 `LabelCap`） | `!ModsConfig.IdeologyActive` 或 `faction.ideos == null`（非人形派系）或 `PrimaryIdeo == null` → 整段跳过（证据 ⑮⑰）；信条列表为空 → 降级为 `他们信奉「{ideo.name}」。` |
| ③ 与我方关系 | `我们与{name}的关系是{敌对/中立/盟友}。其对我们好感度为{goodwill}。` | `Faction.PlayerRelationKind` → `FactionRelationKindUtility.GetLabelCap()`；`Faction.PlayerGoodwill` | **`!faction.HasGoodwill`（隐藏 / 临时派系）→ 整段跳过**：引擎里没有它们与玩家的关系条目，硬取会落入 `RelationWith(other, allowNull: false)` 的缺失分支——先打 `Log.Error`、再返回 dummy（默认中立 / 100），那是兜底值而非真实数据（证据 ⑬⑭㊵）。可谈关系时关系句与好感度句一并写出 |
| ④ 领袖与据点 | `{name}的领袖是{leaderName}。他们在世界地图上共有{n}处定居点，最近的一处距我们约{d}格。` | `Faction.leader`（`Pawn`，取 `NameFullColored`）/ `Find.WorldObjects.Settlements` 按 `Faction` 计数 / `Find.WorldGrid.ApproxDistanceInTiles(a.Tile, b.Tile)` | `leader == null` 时：**隐藏派系整句省略**（「领袖」对它们不适用，写「目前没有已知的领袖」等于把不适用当事实）；非隐藏派系写「目前没有已知的领袖」（如领袖空缺中的部落）；`n == 0` → 据点句整句省略；距离无有效值 → 省略距离子句 |
| ⑤ 成员面貌 | 种族优先：`他们的成员包括{种族A}、{种族B}。`；否则异种人：`他们的成员主要是{异种人A}（约{p}）、{异种人B}（约{q}）。`（`{p}`/`{q}` 为 `float.ToStringPercent()` 结果） | 种族：`FactionDef.pawnGroupMakers[].options[].kind.race` 中的非人类人形种族；异种人：见 FR-9.1 的集合来源（`FactionDef.xenotypeSet` ∪ 主理念 `memes[].xenotypeSet`，`XenotypeChance.chance` + `FactionDef.BaselinerChance` 补差） | **含非人类人形种族 → 只写种族句、不写异种人构成**（两口径**互斥**，理由见下方「成员种族口径」）；无种族时：`!ModsConfig.BiotechActive` 或开关关闭 → 整段跳过；**派系级分布不可信 → 整段跳过**（`IsFactionCompositionUnreliable`：`xenotypeSet == null` 但兵种级另有 `kind.xenotypeSet`——照抄会写出「智人种 100%」；个别 `useFactionXenotypes == false` 的覆盖型兵种**不算**不可信，否则会误伤帝国这类原版派系）；其余情况下列表为空视同全员基础异种人（证据 ㉕㊶㊷） |

**重要取值约束**

- 距离计算必须用 `PlanetTile` 重载 `ApproxDistanceInTiles(PlanetTile, PlanetTile)`（无 `(int,int)` 重载，证据 ⑲）；玩家参照点用「玩家家园据点的 `Tile`」，定位方式照抄引擎自身写法：遍历 `Find.WorldObjects.Settlements` 取 `Faction == Faction.OfPlayer` 的第一个（证据 ㉒）。
- **禁止**使用 `Find.WorldObjects.AllSettlementsOnLayer(...)`：它返回静态共享 `List<WorldObject>`，不可长期持有（证据 ⑱）。
- 科技水平是 `RimWorld.TechLevel` + `RimWorld.TechLevelUtility.ToStringHuman()` 扩展方法（**不在 `Verse` 命名空间**，证据 ⑳）。
- `Ideo` 的名称是公有字段 `name`（小写），**不存在** `Ideo.Name` 属性；信条用 `Ideo.PreceptsListForReading`（**不存在** `Ideo.Precepts`）；理念跟踪器**不存在** `IdeosListForReading` / `HasIdeo`（证据 ⑮⑯）。

**隐藏派系口径（D39）**：隐藏派系与普通派系**共用同一套五段模板**，差别只在各段**判缺**——凡是引擎里没有的字段（与玩家关系、自定义名、领袖、意识形态）一律**整段 / 整句跳过**，绝不写引擎兜底值（默认中立 / 100）或「不适用」的伪事实（如对机械族写「目前没有已知的领袖」）。原因是：隐藏派系常是世界观的重要组成部分（尤以 mod 提供的隐藏派系为甚），值得注入；但它们的数据面比普通派系窄，**宁可少写，不可写假**。具体落点见上表 ①②③④ 各段的「缺省处理」与 FR-11 的指纹口径。

**成员种族口径（D41）**：派系成员若含**非人类的人形种族**（HAR / alien race 类 mod 的种族，如米莉拉），⑤ 段改由「种族」表达（`他们的成员包括{种族名}。`），**不再写异种人构成**。原因：这类种族在 Biotech 的异种人体系里一律登记为智人种（`Baseliner`）——照异种人口径写只会得到「智人种 100%」这类误导内容（实测：米莉拉派系级 `xenotypeSet` 被 mod 作者注释掉、兵种级只声明 `Baseliner`，证据 ㊷）。判定：遍历 `FactionDef.pawnGroupMakers[].options[].kind.race`，取 `race.race.Humanlike && !race.race.IsMechanoid && race != ThingDefOf.Human` 的种族（去重）；**任一非人类人形种族存在即触发**。标签侧同样优先并入**唯一**成员种族名（与 `FindDominantXenotype` 同「唯一才认定」口径），使玩家提到种族名也能带出该派系常识。

**文案风格**：客观第三人称陈述句，不用第一人称口语（那是思想/对白文案的口径），目标是"世界设定条目"的可读性。

### FR-4 触发标签与重要度

| 项 | 定案 |
| --- | --- |
| `tag` | 主词为 `faction.Name`（D3）。**若该派系以某非基础异种人为主**，则并列该异种人名：`{派系名},{异种人名}`（半角逗号分隔，D17）。除此之外**不加**类型词/通用词，避免多派系常识互相挤占注入名额 |
| `matchMode` | `Any`（默认值，单标签下与 `All` 等价） |
| `importance` | 默认 **1.0**（**世界观级最高档**，D11），可在设置里调低（0\~1） |
| `targetPawnId` | `-1`（全局常识，人人可用） |
| `isEnabled` | `true` |
| `category` | `KnowledgeEntryCategory.Lore`（= UI 的「世界观」分类，注入后显式赋值，D7） |

**「世界观级重要性」口径**（D11）：上游 `importance` 只是 0\~1 的 float，**没有档位枚举**；评分公式为 `TotalScore = importance + MatchTypeScore`（关键词命中 `MatchTypeScore = 0.5`，证据 ㉔）。因此「世界观级」落实为两个动作——① `category` 显式置 `Lore`（UI 归类为世界观）；② `importance` 取最高档 `1.0`，使派系常识一旦被触发即拿到排序首位，不被其它低权重常识挤掉。

**匹配语义提醒**（证据 ③）：上游是**子串包含**判定，非分词。派系名若恰好是常见字（如"军""新"），会误触发；这是标签策略的固有代价，登记于 §5 风险表。

**分隔符与多触发词**（D17，证据 ㉗）：上游 `GetTags()` 把 `tag` 按 `,` `，` `、` `;` `；` 五个字符切开，**每个片段都是独立触发词**；而 `CommonKnowledgeEntry.keywords` 字段只被序列化、**不参与任何匹配**。因此：

- 想让异种人名成为触发词，**只能并入 `tag`**，不能写 `keywords` 字段；
- 本 mod 用**半角逗号**作为并列分隔符（`FactionKnowledgeConfig.TAG_SEPARATOR`），即 `{派系名},{异种人名}`；
- 附带风险：派系名自身若含这 5 个字符，会被上游切成碎片，导致按整串 tag 找不回条目——已登记 RK-13。

### FR-5 幂等、补齐与清理

1. **已注入判定**：`CommonKnowledgeAPI.FindKnowledge(factionName)` 取回**候选**条目，再逐条要求两个条件同时成立 → 视为本 mod 注入的条目：① 条目 tag 的**第一段**与派系名全等（借上游 `GetTags()` 切分，D17 下 tag 可能是「派系名、异种人名」）；② `content.StartsWith("【派系】")`。

   **为什么必须补条件 ①**：`FindKnowledge` 是 **tag 子串**匹配（证据 ⑥），查「帝国」会连带命中 tag 为「新帝国」的条目；只用内容前缀判会把别人的条目当成自己的删掉。**为什么用第一段而非整串**：tag 尾段（异种人名）会随派系成员构成变化，只有首段（派系名）是稳定主键（证据 ㉗）。
2. **写入与校正共用一套判定**（FR-11 / D19）：库内**无**条目 → 写入；库内内容与新建内容**逐字一致** → 不写，仅校准好感度基准；差异**仅**来自好感度且差值未达阈值 → 本次不写；其余情况（关系质变、领袖更替、据点增减、成员变化、模板升级）→ `RemoveKnowledge(id)` 后重写。
3. **触发时机**：新档 `StartedNewGame()`、读档 `LoadedGame()`、运行中定时轮询（FR-11）三处共用上述逻辑，因此**不存在**「新档必须先删后写」的特殊路径；原 `replaceExisting` 参数随之取消。
4. **不触碰**玩家自己录入的条目：只有带 `【派系】` 前缀的条目才属于本 mod 管理范围。
5. **上游 API 返回 null 时**（`AddKnowledge` 内部异常已被上游 catch 并 `Log.Error`，返回 `null`，证据 ①）→ 记中文告警，继续处理下一个派系，不中断整体流程。

### FR-6 热门 mod 预设适配

目标：不同 mod 的派系设定结构差异很大（自定义字段、自定义命名、无 `techLevel` 等），需要**可插拔的预设**而非 if-else 堆叠。

**设计**（接口先行，先定义再使用）：

```csharp
/// <summary>派系常识预设：判定是否接管某派系，并定制其内容与标签。</summary>
public interface IFactionKnowledgePreset
{
    /// <summary>预设标识，用于日志与设置界面展示。</summary>
    string Id { get; }

    /// <summary>判断该预设是否接管指定派系。</summary>
    bool Matches(Faction faction);

    /// <summary>为该派系产出一条常识（tag / content / importance）。</summary>
    FactionKnowledgeDraft Build(Faction faction);
}

/// <summary>常识草稿：注入前的中间结构。</summary>
public struct FactionKnowledgeDraft
{
    public string tag;
    public string content;
    public float importance;
}
```

- 注册表 `FactionKnowledgePresets`：按**优先级从高到低**依次询问 `Matches`，首个命中者接管；全部不命中则用内置 `DefaultFactionPreset`（即 FR-3 通用模板）。
- 匹配依据（按可靠性排序）：`faction.def.modContentPack?.PackageId` → `faction.def.defName` 前缀 → `faction.def` 上是否存在某 `HediffDef`/`CompProperties` 等特征。
- **异种人侧同构**：另设一套并列接口 `IXenotypeKnowledgePreset`（`Id` / `Matches(XenotypeDef)` / `Build(XenotypeDef)`）与注册表 `XenotypeKnowledgePresets`，默认实现 `DefaultXenotypePreset`（即 FR-9.2 通用模板）。匹配依据改用 `xenotype.modContentPack?.PackageId` / `xenotype.defName` 前缀。
  - **为何两套接口而非一套**：本工程目标框架为 .NET Framework 4.8，**不支持 C# 8 默认接口方法**，一个接口塞两个可选钩子会迫使每个预设实现无关方法；两个小接口更直白。
- **具体适配清单见 [§6 决策表](#6-决策表) D20**（待用户指定）；框架本期落地，预设可零成本追加。

### FR-8 日志与调试

- 全部日志为**中文**，统一前缀 `[派系常识]`。
- **汇总级**无条件输出（`Log.Message`），一次进入游戏至多三条：
  1. 引擎初始化完毕（`GameComponent.FinalizeInit`，证据 ㉜）时输出本 mod 的包标识与加载来源，例：`[派系常识] 本 mod 已加载：包标识 Cancelation.RimtalkAutoFactionInfo，来源 本地 Mods 文件夹。`
  2. 派系 / 异种人两侧各一条计数汇总，例：`[派系常识] 派系常识：候选 7 个，写入 6 条，跳过 1 条（内容一致），…`；定时轮询无写入时保持静默。
  3. 首次同步（新开档 / 读档）两侧跑完后补一条合计，例：`[派系常识] 常识注入完成：派系 6 条，异种人 4 条。`
- **明细级**（仅当 `enableVerboseLog` 或 `Prefs.DevMode` 为真时输出）：**具体写入了哪些派系 / 异种人**及其完整内容，含写入、刷新、跳过、忽略四类，例：`已写入：{完整内容}`。
- 异常一律 `Log.Error` 且**单个对象失败不中断整体**（逐个派系 / 逐个异种人 try/catch，且两类互相隔离）。

### FR-9 异种人常识（需 Biotech DLC）

与派系常识**同构**：同一对钩子（FR-1）、同一套幂等与补齐机制（FR-5）、同一标签策略与世界观级重要度（FR-4 / D11），只是主体从派系换成异种人。差异点如下。

#### FR-9.0 DLC 门控

- 前置判定 `ModsConfig.BiotechActive`（证据 ㉕）。为假时**整体跳过**，只记一条汇总日志，不报错。
- 未启用时 `DefDatabase<XenotypeDef>` 为空、`FactionDef.xenotypeSet` 为 `null`、`XenotypeDefOf.Baseliner` 为 `null`——**任何访问前都必须先过门控与判空**，否则 NRE（证据 ㉕）。

#### FR-9.1 异种人集合来源（D12）

对 FR-2 筛出的每个**有效派系**，按**游戏生成成员时的同一口径**合并三处来源，得到该派系的异种人概率分布：

| 来源 | 路径 | 说明 |
| --- | --- | --- |
| 派系定义 | `faction.def.xenotypeSet` | 可能为 `null`；遍历只能用 `Count` + 索引器 `set[i]`（**`xenotypeChances` 字段是 private**，无 `XenotypeChances` 属性、无 `AllXenotypes`、无 `GetXenotypeChance`，证据 ㉕） |
| 主理念 | `faction.ideos?.PrimaryIdeo?.memes[i].xenotypeSet` | `MemeDef.xenotypeSet` 是 public 字段；理念可追加异种人倾向（证据 ㉕） |
| **兵种级** | `faction.def.pawnGroupMakers[].options[].kind.xenotypeSet` | `PawnKindDef.xenotypeSet`；游戏在 `PawnGenerator.XenotypesAvailableFor` 里对它**无条件累加**（与 `useFactionXenotypes` 无关，后者只管派系级是否参与）。这是「派系级未声明、特色异种人只写在兵种上」这类派系的**唯一来源**（D40、证据 ㊶） |
| 基础异种人补差额 | `faction.def.BaselinerChance` | `xenotypeSet == null` 时返回 `1f`；非 null 时返回 `1 - Σ(非基础异种人 chance)`（证据 ㉕） |

- 三处来源按**游戏口径累加**（同名异种人 `chance` 相加、跳过基础异种人），并取**并集**作为世界级异种人集合：每个出现的**非基础**异种人 `XenotypeDef` 各生成 1 条常识；基础异种人由 `BaselinerChance > 0` 补差单独成条。
- 单条来源的 `XenotypeChance` 是 `public class`，字段 `xenotype`（`XenotypeDef`）与 `chance`（`float`）均 public（证据 ㉕）。
- 遍历 `PawnKindDef.xenotypeSet` 只读字段、不改 Def、不落盘，无副作用。
- **禁止**靠地图 pawn 统计：新档 `StartedNewGame()` 时玩家地图上只有己方 pawn，没有敌对派系成员（证据 ㉕）。

#### FR-9.2 内容模板

前缀 `【异种人】`（D15），单行无换行（证据 ⑧），世界观级重要度（D11）。

| 段 | 模板 | 取值来源 | 缺省处理 |
| --- | --- | --- | --- |
| ① 是什么 | `【异种人】{LabelCap}：{description}` | `XenotypeDef.LabelCap`（继承自 `Def`）、`XenotypeDef.description`（继承自 `Def`） | `description` 为空则退用 `descriptionShort`（`[MustTranslate]`，证据 ㉕）；两者皆空则只留异种人名 |
| ② 标志性基因 | `标志性基因：{g1}、{g2}、{g3}、{g4}。` | `XenotypeDef.genes` / `XenotypeDef.AllGenes`（同引用），取 `GeneDef.LabelCap` | `genes.Count == 0` → 写「没有任何特殊基因，是自然演化的人类。」（基础异种人即此情况，证据 ㉕）；`xenotypeGeneCount == 0` → 整段跳过 |
| ③ 出没派系 | `他们主要在{派系A}、{派系B}出没。` | 反向索引 FR-9.1 的结果 | 开关 `includeFactionXenotypeRefs` 关闭、或无派系引用 → 整段跳过 |

**反向索引口径**（FR-9.2 ③）：索引 = 遍历 FR-2 筛出的**有效派系**，取各派系的 FR-9.1 **显式集合**（`FactionDef.xenotypeSet` ∪ 主理念 `memes[].xenotypeSet` ∪ 兵种级 `PawnKindDef.xenotypeSet`），建立「异种人 → 派系名」映射。**不含基础异种人补差**——若含，则每个派系都会把智人种列为「出没派系」，列表噪声极大。索引建立必须先于条目遍历（`FactionKnowledgeComponent` 中先 `BuildXenotypeFactionIndex` 再取条目集合）。

**标志性基因的挑选口径**（复用游戏自身的展示顺序，不自创排序）：

1. 候选 = `xenotype.genes` 中 `displayCategory != GeneCategoryDefOf.Miscellaneous` 的基因（`GeneCategoryDefOf.Miscellaneous` 为 public，证据 ㉕）；
2. 排序键：`gene.displayCategory.displayPriorityInXenotype` 降序 → `gene.displayOrderInCategory` 升序（两者均 public，证据 ㉕）；
3. 取前 `xenotypeGeneCount` 个。
4. 可选的类型标注（`biostatArc > 0` → 超凡基因；`biostatMet` 符号 → 增益/代价，证据 ㉕）默认**不写**，避免文案噪声；仅在预设里需要时启用。

#### FR-9.3 标签与幂等

- `tag = XenotypeDef.LabelCap`（如「骠骑种」），`matchMode = Any`（D14）。**不加**通用词。
- 幂等判定与清理：`FindKnowledge(LabelCap)` 中 `content.StartsWith("【异种人】")` 的条目属本 mod 管理范围；新开档先删后写，读档缺失才写（同 FR-5）。
- 与派系条目**同 tag 撞车**时不覆盖、两条都保留，仅记日志告警（[§6 决策表](#6-决策表) D23）。

### FR-10 条目扩展开关（可提取 / 可匹配）

两类常识条目（派系、异种人）一律**显式**开启两个扩展开关（D18）：

| 开关 | 取值 | 含义（证据 ㉘） |
| --- | --- | --- |
| `canBeExtracted` | `true` | 条目内容可被**提取**，拼进下一轮的链式匹配文本，充当后续匹配的线索 |
| `canBeMatched` | `true` | 条目可被**链式匹配**（第 2 轮起）命中 |

- 实现方式：`CommonKnowledgeAPI.AddKnowledgeEx(tag, content, importance, KeywordMatchMode.Any, targetPawnId: -1, canBeExtracted: true, canBeMatched: true)`。
  **不可**用 `AddKnowledge`：它完全不写这两个开关，而 `ExtendedKnowledgeEntry` 侧表新建时默认值是 **false**，等于条目既不提供链式线索、也不能被链式命中（证据 ㉘）。
- `targetPawnId = -1` = 不限定殖民者，任何殖民者都可匹配（`FactionKnowledgeConfig.TARGET_PAWN_ALL`）。
- **生效前提**：上游「常识链式匹配」设置默认**关闭**（`enableKnowledgeChaining` 默认 `false`），关闭时除第 1 轮外不再匹配，本项无害但也无效；开启后轮数由 `maxChainingRounds`（默认 `2`，UI 滑块 1\~5）控制。此前提登记为 RK-15。

### FR-11 内容校正与定时刷新

派系常识里含**易变数据**（③ 关系与好感度、④ 领袖与据点数量/距离、⑤ 成员构成、② 主流意识形态）。若只在开档写入一次，长局游玩后条目会与事实脱节——尤其好感度会**永久停在开档快照**。故写入与校正**共用一套比对式逻辑**（D19），三处触发：

| 触发点 | 说明 |
| --- | --- |
| `StartedNewGame()` | 新档：库内必然无条目 → 全部写入 |
| `LoadedGame()` | 读档：逐条比对，缺失则补、陈旧则重写、一致则不动 |
| `GameComponentTick()` | 运行中：每 `REFRESH_INTERVAL_TICKS`（2500 tick = 1 游戏小时）轮询一次 |

**每个有效派系的判定顺序**：

1. 库内**无**本 mod 条目 → 写入（新条目**不受**冷却限制）。
2. 库内内容与新建内容**逐字一致** → 不写，仅校准各项基准。
3. **质变**：质变指纹相对上次写入发生变化 → **立即重写，不受冷却限制**（FR-12）。普通派系指纹 = `PlayerRelationKind`（敌对 / 中立 / 盟友）翻转；**隐藏 / 临时派系改用固定键 `NoRelation`**（它们 `HasGoodwill` 为假、无可谈关系，硬取会触发引擎 `Log.Error` 并返回兜底值，故不取关系而取固定键，见 D39）；我方派系指纹 = 派系名 + 据点集合 + 飞船集合 + 殖民者数 + 奴隶数（FR-13）。
4. 差异**仅**来自好感度数值，且 `|当前 − 上次写入| < GOODWILL_REFRESH_THRESHOLD`（10）→ 不写（此判定与冷却无关）。**我方派系不参与本步**（对玩家自身无好感度可言，见 FR-13）；**隐藏派系内容里本就没有好感度句**，同样不适用。
5. **非质变**改动（好感度累积、领袖更替、据点增减、成员变化、建立时长与财富增长、模板升级）→ 距上次写入未满 `REWRITE_COOLDOWN_TICKS`（3 天）则**本轮继续等待**，满了才重写（FR-12）。

**「仅好感度波动」怎么判**：把库内内容里的「上次写入的好感度句」（`FACTION_SEG_GOODWILL` 套上次值）**整句替换**为「当前好感度句」。该句模板固定、数值唯一，替换是安全的；替换后若与新建内容逐字相同，即证明其它各段都没变。任一前提不成立（无基准 / `HasGoodwill` 状态变化 / 其它段变化）都照常重写。

**为什么用内容逐字比对而非逐字段判断**：一次覆盖全部易变段，不必为每个字段维护脏标记；且本 mod 后续升级内容模板后，旧条目会在下次触发时自动升级。

**好感度基准的存放**：`Dictionary<int /* faction.loadID */, int /* 上次写入的好感度 */>`，仅存内存、**不持久化**（证据 ㉚）。读档后为空，会保守地重写一次，从而顺带校正存档期间产生的陈旧内容。

**范围与开销**：

- 异种人条目**不参与**定时刷新——其内容（描述、基因、出没派系）几乎不变，只做「缺失才补」。
- 轮询常态开销 = 每个派系一次「查库 + 拼串比对」（派系数通常 ≤ 20）；未产生写入时保持静默、不输出日志。
- 本节的比对式统一覆盖了 FR-5.2/5.3，故不再需要 `replaceExisting` 这类特殊路径。

### FR-12 非质变覆写冷却与调试开关

**为什么需要**：FR-11 的「检测」很便宜（只查库 + 拼串），但**写入**会让上游删条重建。好感度、据点、距离这类数据在长局里持续小步变化，若每次检出差异就写库，会在几小时内反复改库——对玩家浏览常识库的体验（条目 id 变化、列表闪动）与上游日志都不友好。

| 规则 | 值 | 说明 |
| --- | --- | --- |
| 校正**检测**间隔 | `REFRESH_INTERVAL_TICKS` = 1 游戏小时 | 只查库 + 拼串，不写库、不打日志 |
| **非质变**覆写冷却 | `REWRITE_COOLDOWN_TICKS` = 3 游戏天 | 距上次写入未满冷却则本轮跳过（记 Detail 日志） |
| **质变** | 无冷却 | 质变指纹相对上次写入发生变化 → 立即重写（普通派系 = 关系种类翻转；隐藏派系 = 固定键 `NoRelation`；我方派系见 FR-13） |
| 新条目 | 无冷却 | 库内无条目 → 直接写入 |
| 调试覆写冷却 | `DEBUG_REWRITE_COOLDOWN_TICKS` = 1 游戏小时 | 开发者菜单「快速刷新」开启时生效 |

**「质变」的判定**：与上次写入时记录的**质变指纹**做字符串比对。普通派系指纹 = `PlayerRelationKind`（敌对 / 中立 / 盟友）；**隐藏 / 临时派系取固定键 `NoRelation`**（无可谈关系，见 D39）；我方派系指纹 = 派系名 + 据点集合 + 飞船集合 + 殖民者数 + 奴隶数（FR-13）。基准存于 `Dictionary<int /* faction.loadID */, string>`，仅内存、**不持久化**；无基准（刚读档）时视为质变，以便立即校正陈旧内容。

**调试开关**：`KnowledgeDebug` 用 `[DebugAction]` 在开发者菜单注册按钮（`RimtalkAutoFactionInfo` → 切换快速刷新（覆写冷却 3天 ↔ 1小时）），点击即在 3 天与 1 小时之间切换非质变覆写冷却，并在日志里回报当前生效值；开关只在内存、**不随存档保存**。用 `[DebugAction]` 而非 ModSettings 的原因：S4 尚未实施，且调试需求是「随手可点、不污染玩家设置界面」。

**取舍记录**：检测间隔（1 小时）与写入冷却（3 天）**刻意分开**——检测便宜、可以密；写入有副作用、必须稀疏。将来若要更省，只需调大 `REFRESH_INTERVAL_TICKS`，不必动冷却。

### FR-13 我方派系介绍

为**玩家自己的派系**（`faction.IsPlayer`）单独写一条常识：殖民者对白提到自己派系名时，能带出「我是谁、我在哪、我有什么」。内容走**独立**模板（不套用 FR-3 的五段：我方派系没有「与我方关系 / 好感度」可言，且需要据点名、飞船名、财富等专属信息）。

**前缀与标签口径**：内容前缀同 `【派系】`（D8 幂等标记，两类派系共用同一管理范围）；标签主词同 `faction.Name`（走 FR-4 / D3）。普通派系仍按 FR-4 并列特征异种人名；**我方派系的标签 = 派系名 + 我方逆重飞船名**（玩家 / 殖民者提到飞船名也能带出该条目，D35），**不并列特征异种人名**（我方派系内容不含「成员构成」段，并列会错配）。

| 段 | 模板 | 取值来源 | 缺省处理 |
| --- | --- | --- | --- |
| ① 身份 | `「{name}」是我们自己所属的派系。` + `我们的开局剧本是「{剧本名}」。` | 派系名取 `Faction.Name`；剧本名取 `Find.Scenario.name`（D38） | 身份句**始终保留**；剧本句在读不到剧本 / 剧本名为空时**省略** |
| ② 人口 | `我们有{殖民者数}名殖民者{附加}。`，附加形如 `，另有2名临时成员、1名囚犯、3名奴隶` | 遍历 `PawnsFinder.AllMapsCaravansAndTravellingTransporters_Alive`，按**互斥优先**顺序判定：囚犯（`Pawn.IsPrisonerOfColony`）→ 奴隶（`Pawn.IsSlaveOfColony`）→ 临时成员 → 殖民者（`Pawn.IsFreeNonSlaveColonist`） | 殖民者数**始终显示**（可为 0）；附加子句**只列人数非零的类别**，三类全零则整句只有殖民者数 |
| ③ 机械族 | `我们还有{型号构成}。`，型号构成形如 `3台清扫机、2台建造者` | 需 Biotech：同一遍历范围内 `Pawn.IsColonyMech` 逐台按其 `kindDef.LabelCap` **分型号计数**，**按型号名升序**输出 | **未启用 Biotech → 整段跳过**；启用但 0 台 → 替代句 `我们目前没有友方机械族。` |
| ④ 据点 | `我们的据点是{据点列表}。` | 遍历 `Find.Maps` 取 `IsPlayerHome` 且**非**飞船着陆生成的地图，取其 `map.Parent.LabelCap`（`MapParent` → `WorldObject.LabelCap`），多据点**全部列出**并以 `、` 连接 | 无据点 → 替代句 `我们目前还没有固定的据点。` |
| ⑤ 气候 | `殖民地所在位置的气候是{生物群系名}。` | `Find.AnyPlayerHomeMap.Biome.LabelCap`（`Map.Biome` 即 `TileInfo.PrimaryBiome`） | 无主基地地图 / 群系不可读 → **整段跳过** |
| ⑥ 逆重飞船 | `逆重飞船「{飞船名}」已在此停留{停留时长}。` | `ModsConfig.OdysseyActive` 为真时遍历 `Find.Maps`：`GravshipUtility.PlayerHasGravEngine(map)` 判定 + `GravshipUtility.TryGetNameOfGravshipOnMap(map, out name)` 取名；停留时长 = `TicksGame − map.generationTick`，**仅当 `map.wasSpawnedViaGravShipLanding` 为真时**才能反推 | 无 Odyssey / 无飞船 → **整段跳过**；有飞船但读不到着陆时刻 → 降级为 `我们有一艘逆重飞船「{飞船名}」。`（**不编造时长**） |
| ⑦ 建立时长 | `这个派系已经建立了{时长}。` | `Find.TickManager.TicksGame` | `TicksGame` 不可得 → 记 0（即「刚建立」） |
| ⑧ 财富 | `主基地的财富约为{财富值}。` | `Find.AnyPlayerHomeMap.wealthWatcher.WealthTotal`（`float` → 取整） | 无玩家据点地图，或读取抛异常（地图地形索引越界）→ 整段跳过并**只告警一次**（RK-23） |

- **剧本名口径**（证据 ㊴ / D38）：取 `Find.Scenario.name`（`[MustTranslate]` 本地化文本，即玩家在剧本界面看到的原文，如「迫降」「失落的部落」）。**只取名字**——不取 `summary` / `description`（二者含 `\n`，会破坏上游单行格式），名字本身也过一次 `ToSingleLine` 消隐患；**不反查 `ScenarioDef`**（`Scenario` 无 `def` 字段，且读档后是 Scribe 反序列化的新实例，引用比对失效）。剧本句**不进质变指纹**，交由覆写冷却控制。
- **人口的四类口径**（证据 ㊱）：**殖民者** = `IsFreeNonSlaveColonist`（自由人，不含奴隶 / 囚犯 / 临时成员）；**临时成员** = `QuestUtility.IsQuestLodger()`（任务寄居者：难民、来做客的等）**或** 由我方招待的来客（`HostFaction == 我方 && guest.GuestStatus == GuestStatus.Guest`）；**囚犯** = `IsPrisonerOfColony`；**奴隶** = `IsSlaveOfColony`。
- **人口遍历范围**：`AllMapsCaravansAndTravellingTransporters_Alive`（所有地图上 + 商队 / 运输船 / 当前逆重飞船里活着的单位），故**外派商队中的殖民者也计入**；`!pawn.RaceProps.Humanlike` 排除动物，亚人由 `IsColonist` 自身排除；**机械族非人形，故 ③ 段的统计必须放在人形过滤之前**，否则会被一并排掉。名单中「地图」一侧实为 `mapPawns.AllPawns`（已生成 + 容器 / 休眠舱内未生成者），**尸体已被 `AllPawnsUnspawned` 内部排掉**，故无需再判 `Dead`。（证据 ㊱）
- **机械族口径**（证据 ㊳）：台数走 `Pawn.IsColonyMech`（= `ModsConfig.BiotechActive && RaceProps.IsMechanoid && Faction == 我方 && MentalStateDef == null && (HostFaction == null || IsSlave)`，**自身已含 Biotech 门控**）；**型号取 `Pawn.kindDef.LabelCap`**（机械族的「型号」即其兵种，如清扫机 / 建造者），按**型号名升序**输出「N 台某型」——排序是为内容可复现（`Dictionary` 遍历顺序会随增删而变）。**不自行判断 Def / 自行拼条件**。（曾取 `MechanitorUtility.IsColonyMechRequiringMechanitor()` 写「失去监管」子句，现按用户要求移除，见 D37。）
- **气候口径**（证据 ㊳）：取主基地地图所属生物群系名（`Map.Biome.LabelCap`，而 `Map.Biome` 即 `TileInfo.PrimaryBiome`），与游戏内世界地图的「生物群系」口径一致；只在**主基地**（`Find.AnyPlayerHomeMap`）上取，与 ⑧ 财富同源。
- **时长文案**：统一用 `GenDate.ToStringTicksToPeriod(ticks, allowSeconds: false)`（游戏本地化的「X 年 Y 天」式），**不自行拼数字**。
- **据点排除飞船地图**：飞船着陆生成的地图其 `Parent.LabelCap` 由飞船名派生，与 ⑥ 段重复，故 ④ 段跳过 `map.wasSpawnedViaGravShipLanding` 的地图。
- **建立时长的口径局限**（已知取舍）：`Faction` **没有任何记录创建时刻的字段**（证据 ㉝），世界生成期的 tick 也未与本派系挂钩，故「建立时长」只能退化为**游戏已进行时长**（`TicksGame`）。若有 DLC/存档引入更精确来源，此项再收紧。
- **质变指纹**（对接 FR-11 / FR-12）：我方派系的「质变」= **派系名 + 据点集合 + 飞船集合 + 殖民者数 + 奴隶数**（拼接成分隔符指纹字符串），五者任一变化即视为质变、**立即重写**；⑦ 建立时长、⑧ 财富、**囚犯数与临时成员数**（难民 / 来客来去频繁）、**① 剧本名、③ 机械族型号构成、⑤ 气候**（剧本名整局不变、只有切换语言时才变；③ 机械族型号构成与 ⑤ 气候是用户明确要求「不立刻更新」——机械族会持续充放电、机械师更替也频繁，进指纹会导致高频立即重写；型号名排序保证同集合下内容稳定）**刻意不进指纹**，其更新交由 `REWRITE_COOLDOWN_TICKS`（3 天）冷却控制。
- **好感度一律不取**：我方派系既不参与 FR-11.4 的「仅好感度波动」判定，**也不发生好感度取值本身**——`PlayerGoodwill` / `PlayerRelationKind` 对玩家派系自身会触发引擎报错并 NRE（RK-22 / 证据 ㉞），必须在取值表达式处先判 `faction.IsPlayer`。
- **财富读取须就地降级**：`WealthTotal` 不是纯读取——它会按需触发**全图财富重算**，而重算按 `cachedTerrainMarketValue[terrainDef.index]` 取地形价值，遇到未被 `DefDatabase` 登记的地形（`Def.index` 停在默认 `ushort.MaxValue`）会抛 `IndexOutOfRangeException`。该异常与原版告警链路（`Alert_NeedJoySources`）同源，**不是本 mod 引起的**；但既然本 mod 也会读它，就必须 try/catch 只省略财富段（RK-23 / 证据 ㉟），不能让外部数据异常连累整条我方派系条目。
- **名字会变，故识别不靠名字**（D35）：我方派系的标签含派系名与飞船名，两者都会变——开档时玩家派系**尚无自定义名**（`HasName` 为假，`Name` 回退为 `def.LabelCap`，即「新移民」），玩家改名后标签变；飞船建成或改名后标签也变。若仍按「主键 = 当前派系名」查库，改名后**查不到旧条目**：旧条目会以旧名残留成重复项，且提到旧名还会命中陈旧内容。故对我方派系改用**内容里的固定句** `是我们自己所属的派系。`（`PLAYER_SEG_IDENTITY_SUFFIX`）识别条目（与名字无关），重写时先删旧的再按新名 / 新飞船名建新的。**旧名不保留**（用户选定）：改名后提到旧名不再命中，库里始终只剩一条。
- **存量存档自动迁移**：以旧口径写入（无飞船名标签）的条目，也会被上述固定句识别到；首次同步若判定需重写（改名 / 飞船变化 → 指纹变化 → 质变），旧条目一并删除，不留重复。若无需重写（内容一致）则原样保留，不做多余写入。
- **依赖降级**：无 Odyssey DLC 时 ⑥ 段整体缺席且不报错；无 Biotech 时 ③ 机械族段整体缺席（无机械族可言，写了只是噪声）；无 Ideology / Biotech 时 ② 人口段与 ⑧ 财富段照常（人口判定不依赖 DLC，奴隶判定在无 Ideology 时为 0）。（证据 ㊱、㊳、㉜）

### FR-14 派系界面「实际成员」显示（Harmony 补丁，可开关）

**动机**：游戏自带的派系界面在 HAR 种族 / 兵种级异种人派系上会显示「智人种 100%」（原因此处与 FR-3 ⑤ / D41 同源，见证据 ㊷）。本项把本 mod 已有的「实际成员」口径**追加**到派系界面，作为**可选增强**：默认开启，玩家可在「选项 → Mod 设置」中关闭。

**为什么用 Harmony（D42 修订 D10）**：派系界面的文本由引擎**属性 getter**产出，没有可用的事件 / `GameComponent` 钩子；D10「零 Harmony」只针对**常识注入路径**，本项属**界面增强**，故以两个最小化的属性 Postfix 补丁实现（不改变 D10 注入路径的零补丁前提）。

| 项 | 定案 |
| --- | --- |
| 补丁宿主 | ① `FactionDef.Description` 属性 getter——派系列表悬停提示（`FactionUIUtility` 两处 tooltip + `WorldFactionsUIUtility` + `Dialog_RewardPrefsConfig`）；② `Faction.GetReportText` 属性 getter——派系信息卡「描述」条目（`StatsReportUtility.DescriptionEntry(Faction)` → `Dialog_InfoCard`）（证据 ㊸） |
| 追加内容 | **只输出游戏自身看不出的部分**：含非人类人形种族（HAR / alien race）→ **对齐原版成员段排版**的名称块（着色标题行「成员种族:」+ 每行 `  - {种族名}`，**只列名称不写占比**——种族在 Def 层没有概率声明，`PawnKindDef.race` 是单一确定值）；否则派系级分布不可信 → `他们的成员涉及以下异种人：{异种人名}。`（**同样不写占比**——兵种级集合是无条件并集，同一异种人可能只出现在个别特殊兵种上，写占比会误导）；其余情形**返回 `null` 不追加**（游戏自带「成员异种人概率」已正确，再写只是噪声） |
| 追加位置 | 原文本末尾，以空行分隔（原文本为空时直接返回块，避免前导空行）；不改动原文本本身 |
| 开关 | 设置项 `showCompositionInFactionUi`，默认 `true`；关闭后两个补丁立即返回原值（`FactionCompositionUi.Enabled`，设置未载入时按「显示」处理） |
| 异常隔离 | 构建整体 try/catch（`FactionCompositionUi.BuildSafely`）：这两处属性**每帧都可能被 tooltip 触发**，异常会连累整个派系页并刷屏，故任何异常一律降级为「本次不追加」+ `WarnOnce`（RK-30） |

- **不依赖 `Faction` 实例**：`FactionDef.Description` 可能在无存档界面被访问，故构建器只读 `FactionDef` 级数据（`RaceKnowledgeBuilder` / `XenotypeKnowledgeBuilder` 新增 `FactionDef` 级重载）。
- **不影响常识注入**：常识内容取 `Def.description` **字段**（不经这两个属性，FR-3 ①），补丁不改注入内容，也不影响 `RimTalkMemoryBridge` 的查库与幂等判定。
- **Harmony 依赖**：运行时由 `brrainz.harmony` 提供（`About.xml` 已 `loadAfter`）；游戏自身 `Managed` 目录**不含** `0Harmony.dll`，编译期从工坊 HarmonyMod 引用、`Private=false`（证据 ㊺）。补丁集用独立 Harmony ID（`HARMONY_ID`）便于排查冲突。
- **外星种族只列名称、不写占比**：种族在 Def 层**没有概率声明**——`PawnKindDef.race` 是单一确定值（`Verse\PawnKindDef.cs` L248），`PawnGenOption` 只有 `kind` + `selectionWeight`（`RimWorld\PawnGenOption.cs` L33\~L37），`FactionDef` 无种族分布字段；种族占比只能由兵种权重**估算**或实测已生成成员，二者都不是权威人口占比，故**只列名称**。（异种人层倒是真有概率表：`PawnGenerator.XenotypesAvailableFor`，但那是**异种人**口径，且是 per-kind、返回共享静态字典，不在本项范围。）
- **排版对齐原版成员段**：种族块按 `(标题 + ":").AsTipTitle() + "\n" + 名称.ToLineList("  - ", false)` 拼装（原版范式见 `RimWorld\FactionDef.cs` L199 / L217\~L218；`AsTipTitle` = `Verse\ColoredText.cs` L351，`ToLineList` = `Verse\GenText.cs` L841\~L859），新增常量 `UI_COMPOSITION_MEMBER_RACES_TITLE` / `UI_LIST_ITEM_PREFIX`；前导空行仍由 `FactionCompositionUi.Append` 负责，故不存在空行偏差。

## 4. 非功能需求

| 项 | 要求 |
| --- | --- |
| 性能 | 注入的**重活**（遍历据点算距离、拼串、查库）只在新档一次 + 每读档一次 + 定时校正时执行；规模为 O(派系数 × 据点数 + 派系数 × 异种人数)，派系数通常 < 20、据点总数 < 200、异种人数 < 20，单次开销可忽略。定时校正按 `REFRESH_INTERVAL_TICKS`（2500 tick）节流（FR-11），**不得**在 `GameComponentUpdate`（每帧）或节流判定之前做任何扫描 |
| 刷新开销 | 校正的常态是「查库 + 拼串比对」，未产生写入时零写入、零日志（FR-11） |
| 存档兼容 | 只新增常识条目，不改原版与上游任何存档字段；注入条目随存档自然保存（证据 ⑤）。旧档可直接装/卸 |
| 依赖隔离 | 仅 `RimTalkMemoryBridge` 一个文件 `using RimTalk.Memory`，其余代码不感知上游类型（D9） |
| 补丁隔离 | Harmony 补丁只集中在 `Patches\FactionCompositionUiPatch.cs`，且只在 `FactionInfoMod` 构造期 `PatchAll` 一次；补丁体只做「读 Def + 拼串」，不写状态、不落盘，异常就地 catch 降级（FR-14） |
| 缺失依赖 | 若上游常识库取不到（`Current.Game == null`、上游未启用），记一次中文告警并静默退出，不抛异常、不刷屏 |
| DLC 降级 | 无 Biotech 时异种人一遍整体跳过且不报错（FR-9.0）；无 Ideology 时意识形态段跳过（FR-3 ②）。两项降级互不耦合 |
| 版本兼容 | 只声明 1.6；`supportedVersions` 单条 |

## 5. 风险与护栏

| # | 风险 | 护栏 |
| --- | --- | --- |
| RK-1 | 派系名是常见字 → 对白频繁误触发 | 标签策略固有代价（D3）。缓解：日志暴露注入清单便于排查；必要时后续提供「标签排除名单」设置。（我方派系条目虽已纳入（D33），但其触发词同样只是派系名本身，不额外放通用词） |

| RK-3 | `PlayerGoodwill` 在无关系时打 Error 日志 | 必须先用 `faction.HasGoodwill` 门控（FR-3 ③） |
| RK-4 | 内容含换行破坏导入导出格式 | 内容强制单行（FR-3 / FR-9.2），代码里不得出现 `\n` |
| RK-5 | 读档补齐把玩家手动删除的条目加回 | 已知行为（D8 / D22），先不处理，观察反馈 |
| RK-6 | 在上游未启用/未加载时崩溃 | 桥接类内全部 try/catch + 前置空库判定（FR-8） |
| RK-7 | 据点距离在多层星球（Odyssey）下取到 `int.MaxValue` | 距离值无效（`<= 0` 或 `>= int.MaxValue`）时省略距离子句（FR-3 ④） |

**目录约定**

- **按职责分文件夹、命名空间保持扁平**：全部类型统一在 `RimtalkAutoFactionInfo` 命名空间下（工程规模小，分层命名空间只增加 `using` 噪音）。子文件夹仅作物理归档，**移动文件不影响任何 `using`**；新增文件按上表归位。
- SDK 风格 csproj 用默认 glob 收集 `**/*.cs`，无需为新增文件夹改 csproj。

**csproj 要点**

- `TargetFramework` = `net48`（同其它 mod 工程口径）；`Private=false` 引用（不复制上游 dll 进 Assemblies）。
- 引用：`Assembly-CSharp`、`UnityEngine.CoreModule`（`Mod.DoSettingsWindowContents(Rect)` 需要，Rect 属该程序集）＋ `RimTalkMemoryPatch` ＋ `0Harmony`（FR-14 补丁需要）。
- 路径属性集中声明，不散落字面量：

```xml

  <RimWorldDir>..\..\..\..\</RimWorldDir>
  <ManagedDir>$(RimWorldDir)RimWorldWin64_Data\Managed\</ManagedDir>
  <Workshop294100>$(RimWorldDir)..\..\workshop\content\294100\</Workshop294100>
```

- **Harmony 程序集来源**：游戏自身 `RimWorldWin64_Data\Managed` **不含** `0Harmony.dll`，须从 HarmonyMod 工坊（`2009463077\Current\Assemblies\`）引用；`Private=false` 不复制进本 mod `Assemblies`，运行时由 `brrainz.harmony` 提供（证据 ㊺）。

- **输出目录按配置隔离（出包流水线前提，见 `rimworld-mod-release` 技能）**：`Release → ..\Assemblies`（入库）、`Debug → ..\AssembliesDebug`（`.gitignore` 忽略），另配 `AppendTargetFrameworkToOutputPath=false`（否则会多出 `net48\` 一层）与 `IncludeSourceRevisionInInformationalVersion=false`（dll 字节只由源码决定，跨 commit 可复现）。**不再用 `AfterTargets="Build"` 复制**——那会让 Debug 编译覆盖入库的发行 dll。

**打包流水线**（`Tools\Build-Release.ps1`，复制自 `rimworld-mod-release` 技能模板）：

- 一次运行完成：读 `modVersion` → 工作区脏 / 同名 tag 告警（不阻塞）→ 依次编译 Release、Debug → 按白名单组装 `dist\stage\{release,debug}\RimtalkAutoFactionInfo\` → Debug 包改写包内版本号为 `<版本>-debug` → 产出两个 zip。

## 9. 验收标准

### 9.1 派系常识

1. **新档**：开局后 RimTalk 常识库（`RimTalk_Memory` 主标签页）中出现每个有效派系各 1 条 `【派系】…` 条目，**分类显示为「世界观」**。
2. **世界观级重要性**：任取一条派系常识，其 `importance` 为 **1.0**、`category` 为 `KnowledgeEntryCategory.Lore`（UI 归入「世界观」）；把设置里重要度调低后重注入，条目重要度随之变化。
3. **内容正确性**：随机抽 2 个派系，条目中的派系类型、科技水平、关系种类、据点数量与世界地图实际一致。
4. **触发有效性**：在 RimTalk 标签测试工具中输入含某派系名的对白文本 → 该派系常识被匹配到，且在注入结果中排序靠前（满重要度）。对**以某非基础异种人为主**的派系，输入**只含该异种人名**的文本，同样能匹配到该派系常识（D17）。
5. **幂等**：同一存档连续读档 3 次，条目数量不增长。
6. **旧档补齐**：对一个「装本 mod 之前就已存在」的存档读档后，常识库被补齐。
7. **降级**：关闭总开关后重开档，常识库无 `【派系】` 条目；卸载本 mod 后上游功能不受影响。
8. **无 Ideology DLC**：不报错，意识形态段自动缺席，其余段正常。
9. **仅有玩家派系场景**：某些剧本下只有一个玩家派系（无其它有效派系）时，写入**我方派系 1 条**（FR-13）且不报错。

### 9.2 异种人常识（需 Biotech）

10. **集合正确性**：新档后把日志中的异种人清单与「有效派系的 `FactionDef.xenotypeSet` ∪ 其主理念 `MemeDef.xenotypeSet` ∪ 各兵种 `PawnKindDef.xenotypeSet`（再按 `BaselinerChance` 补基础异种人）」逐一对照，**不多不少**（D40）。
11. **内容与基因顺序**：任取一条 `【异种人】…` 条目，其「标志性基因」列表与游戏内该异种人信息卡上按「类别优先级降序 → 类别内顺序升序」排列的**前 N 个非 Miscellaneous 基因**一致（`N = xenotypeGeneCount`，默认 4）；`xenotypeGeneCount = 0` 时该段整体缺席。
12. **基础异种人**：`XenotypeDefOf.Baseliner`（中文「智人种」）条目存在，其基因段写「没有任何特殊基因，是自然演化的人类」而非空白。
13. **双向引用自洽**：任取一个派系条目，其第 ⑤ 段列出的异种人，其条目「出没派系」段必含该派系；反之亦然（互相印证，无单向悬空引用）。
14. **无 Biotech DLC**：不报错、无 `【异种人】` 条目，且派系条目第 ⑤ 段缺席，其余段正常（与第 8 项相互独立）。
15. **异种人开关**：关闭 `includeXenotypes` 后无 `【异种人】` 条目但派系条目第 ⑤ 段仍在；关闭 `includeFactionXenotypeRefs` 后两处引用段均缺席；连续读档 3 次条目数不增长（幂等）。

### 9.3 全局

16. **编译**：Debug / Release 双配置 0 错误 0 警告（`dotnet build 1.6\Source -c Debug --nologo -v m` 与 `-c Release`）。
17. **预设适配**（D20 落地后）：被适配 mod 的派系/异种人条目内容明显优于通用模板，且未适配对象仍走 `DefaultFactionPreset` / `DefaultXenotypePreset` 不受影响。

### 9.4 我方派系介绍（FR-13）

18. **条目存在**：新档 / 读档后常识库中存在一条内容形如 `【派系】「{我方派系名}」是我们自己所属的派系。…` 的条目，其 `category` 为「世界观」、`importance = 1.0`。
19. **内容正确性（有 Odyssey）**：条目中的据点名与世界地图我方据点**一一对应且全部列出**；若有逆重飞船，飞船名与游戏内一致，停留时长与世界地图/飞船信息一致。
20. **读不到时省略**：飞船停靠在已有地图（读不到着陆时刻）时，内容降级为「我们有一艘逆重飞船「…」。」**不出现编造的时长**。
21. **降级（无 Odyssey）**：无 Odyssey DLC 时不报错，飞船段整体缺席，其余段（身份 / 据点 / 建立时长 / 财富）正常。
22. **质变与冷却**：新增或摧毁一处我方据点（或新增/移除飞船）→ **立即**重写；仅财富或时长增长 → 3 天内不重写、满冷却后重写。连续读档 3 次条目数不增长（幂等）。
23. **财富口径**：条目中的财富值与「主基地地图」的财富面板一致（非全据点合计）。
24. **新档无报错**：创建新档时日志中**不出现** `Tried to get relation between faction … and itself.`，也不出现 `GoodwillSituationManager.GetMaxGoodwill` 的 `NullReferenceException`（RK-22）。
25. **财富读失败可降级**：当地图存在未登记地形导致 `WealthTotal` 越界时，我方派系条目**仍然写入**（只缺 ⑤ 财富段），且日志只出现一次「读取主基地财富失败…」告警（RK-23）。
26. **轮询不刷屏**：开着开发者模式空跑若干游戏小时，日志中**不再**逐小时出现「跳过（非质变改动，覆写冷却中）」（RK-24）。
27. **人口段正确**：条目中殖民者 / 临时成员 / 囚犯 / 奴隶 四类人数与游戏内实际一致（殖民者含外派商队者，不含动物 / 机械体 / 尸体）；附加子句**只列非零类别**，四类中仅殖民者非零时整句只有殖民者数。
28. **人口质变口径**：招募 / 死亡 / 捕获一名殖民者或奴隶 → **立即**重写；囚犯增删、难民 / 来客来去 → 不立即重写，走 3 天冷却（D34）。
29. **无 DLC 降级**：无 Ideology / Biotech 时人口段照常输出且不报错（奴隶数恒为 0）；无 Odyssey 时仅飞船段缺席。
30. **改名不留残条（D35）**：开档后用改名界面把玩家派系从「新移民」改成新名 → 库里**只有一条**我方派系条目，标签与内容均为**新名**；提到旧名「新移民」**不再命中**；提到新名仍能命中。
31. **飞船名进标签（D35）**：建成逆重飞船（Odyssey）后，我方派系条目**立即**重写，标签变为「派系名,飞船名」，内容含飞船段；殖民地提到飞船名能带出该条目。飞船改名后标签与内容同步更新，仍只有一条。
32. **机械族型号段（D37）**：有 Biotech 且拥有友方机械族时，条目 ③ 段**按型号列出**「N 台某型」（如「3台清扫机、2台建造者」），台数与型号与游戏内一致，且**不出现**「失去监管」子句；无机械族时写「我们目前没有友方机械族」；无 Biotech 时该段整体缺席。
33. **气候段（D36）**：条目 ⑤ 段写出主基地所属生物群系名，与世界地图的「生物群系」一致；尚无主基地地图时该段缺席。
34. **开局剧本句（D38）**：条目 ① 身份句之后写出本局剧本名（如「迫降」「失落的部落」），与剧本界面所选一致；读不到剧本时该句缺席；切换语言后该句随冷却重写为对应语言。

### 9.5 隐藏派系注入（D39）

35. **隐藏派系纳入**：新档后常识库中存在原版机械族 / 虫族等隐藏派系的 `【派系】…` 条目（每条 `category` 为「世界观」、`importance = 1.0`）；mod 自带的世界观隐藏派系同样被注入。
36. **不写隐藏派系没有的数据**：上述条目的内容中——**不出现**关系句与好感度句、**不出现**「目前没有已知的领袖」、**不出现**「科技水平为Undefined」；有意识形态 / 成员构成的隐藏派系才写对应段，无者整段缺席。日志中**不出现**引擎 `has null relation with` 的 `Log.Error`（③ 段前置 `HasGoodwill` 守卫 + 指纹取固定键 `NoRelation`）。
37. **降级不误伤普通派系**：非隐藏派系（可谈关系、有自定义名、有领袖）的条目内容与本次改动前**逐字一致**（关系句、好感度句、「没有已知的领袖」句照常出现）。

### 9.6 异种人来源口径修订（D40）

38. **兵种级来源覆盖**：对「派系级未声明 `xenotypeSet`、特色异种人只写在 `PawnKindDef` 上」的派系（如成员混编机械族的 mod 派系），日志中的异种人清单**包含**其兵种级异种人；常识库中存在该异种人的 `【异种人】…` 条目，且其「出没派系」段含该派系名；该派系条目的 `tag` 含该异种人名。
39. **不再误报「智人种 100%」**：上述派系的派系条目**第 ⑤ 段缺席**，日志出现「跳过成员构成段（派系级异种人分布不可读）」明细；对照游戏内该派系实际刷出的成员，异种人与其兵种级设置一致。
40. **原版派系不受误伤**：派系级声明了 `xenotypeSet`、且无兵种级覆盖的原版派系（部落 / 外来者 / 帝国等），成员构成段**照常输出**且与本次改动前**逐字一致**。

### 9.7 成员种族口径（D41）

41. **HAR / alien race 派系写出成员种族**：对成员含非人类人形种族的派系（如米莉拉），其派系条目第 ⑤ 段为 `他们的成员包括{种族名}。`，**不出现**「智人种 100%」等异种人内容；该派系条目的 `tag` 含该种族名（唯一成员种族时）。
42. **不误伤人类派系**：成员均为人类的派系（部落 / 外来者 / 帝国等）**不出现**种族句，第 ⑤ 段仍按异种人口径输出，与本次改动前一致。

### 9.8 派系界面「实际成员」显示（FR-14）

43. **默认追加**：未改设置时，把鼠标悬停到 HAR 种族派系（如米莉拉）的派系列表行 → 悬停提示末尾出现本 mod 追加的**成员种族块**（着色标题行「成员种族:」+ 每行 `  - {种族名}`，**只有名称、无百分比**，与原版「成员异种人概率」段排版一致）；点开该派系信息卡 → 「描述」条目末尾同样出现该块。
44. **不重复、不误伤**：对派系级异种人分布正常的原版派系（部落 / 外来者 / 帝国），悬停提示与信息卡的**文本与本次改动前逐字一致**（不追加任何内容）。
45. **开关生效**：在「选项 → Mod 设置 → Rimtalk Auto Faction Info」中关闭「在派系界面显示实际成员构成」后，上述两处**均不再**出现追加句；重新打开后恢复（无需重开档）。
46. **异常降级**：补丁构建过程若抛异常，界面**不崩、不刷屏**，仅在日志出现一次告警（RK-30）。
